## 保持统计与公式（5）的对应

核心计算为：

$$
C_\ell=\sum_m\omega_{\ell,m}u_{\ell,m}u_{\ell,m}^{\top},
\qquad \omega_{\ell,m}\ge0.
\tag{5}
$$

实现先令 $v_m=\sqrt{\omega_m}u_m$，再按批次累计 $C\mathrel{+}=V^\top V$，其中 V 的每行是一个 $v_m^\top$。沿用先以 float64 吸收权重、再转换为配置累计精度的计算方式，零权重项不参与乘法；不去均值、不归一化、不添加 ridge。原有分块上三角复制继续保留，以保持 C 的计算结果一致。

已移除的内容包括初始化与输入的自定义检查、样本统计计数、独立坐标外积、trace 核对、随机正交投影、特征值检查、diagnose 方法、所有诊断字段，以及提取阶段的两次额外前向。

保持输入、掩码上下文和捕获位置仍由输入准备与模型适配器确定。keep_matrices 只接受 accumulation_dtype、storage_dtype、device、batch_keep 四个配置参数，返回（模块名，C）；旧 QA 种子、投影数量、重放与检查容差等参数已移除。

## 固定写回因子：功能、函数与公式

`MDLM/writeback.py` 接收每层的 K、C 和正则系数 λ，预先求固定右因子 Q；后续由其他模块优化 R，并通过 ΔW=RQ 形成权重增量。本文件不优化 R，也不写入模型权重。

对照《最终逻辑 V1.0》第五节，原实现和精简后的核心求解均与公式（6）～（9）对齐：

| 公式 | 数学内容 | 代码中的对应作用 |
| --- | --- | --- |
| （6） | $\Phi(D\mid R)=\tfrac12\lVert DK-R\rVert_F^2+\tfrac12\operatorname{tr}(DCD^\top)+\tfrac\lambda2\lVert D\rVert_F^2$ | Q 的推导依据；不在此文件中反复优化 D 或 R |
| （7） | $DH=RK^\top$，$H=C+KK^\top+\lambda I$ | 复制 C 后依次加入 KKᵀ 与 λI，保留原计算顺序 |
| （8） | $\xi^\top H\xi\ge\lambda\lVert\xi\rVert_2^2>0$ | 在 C 对称半正定、λ>0 的算法前提下采用 Cholesky 分解 |
| （9） | $HX=K$，$Q=X^\top$，$\Delta W=RQ$ | 解线性系统并返回 Q，不显式求逆；ΔW 在后续模块计算 |

精简后的三个组成部分为：

| 名称 | 功能 |
| --- | --- |
| `WritebackConfig` | 保存逐层 λ、求解精度、Q 存储精度和设备，四项参数的默认值沿用原实现 |
| `stable_frobenius_norm(value)` | 缩放后计算 Frobenius 范数，原计算保持不变，当前供累计参数变化计算调用 |
| `solve_writeback_factor(keys, keep, ridge, settings)` | 构造 H，分解 H=LLᵀ，解 HX=K，再返回指定存储精度、连续布局的 CPU Q；Q 不参与梯度 |

原 `WritebackConfig.check()` 用于配置合法性检查，`relative_residual()` 用于方程残差核对，`WritebackSolveError` 用于附带诊断报告的异常包装，均已移除。耗时、内存、谱尺度、四次方程残差和阶段报告也已删除；Cholesky 无法分解时由 PyTorch 直接报错，不自动调整 λ 或加入 jitter。

`p3` 配置现在只接受 `ridge_by_layer`、`compute_dtype`、`storage_dtype`、`device`；默认全流程配置无需修改。`solve_writeback_factor` 现在只返回 Q，调用方已同步，不保留旧报告返回值。

本轮 22 项相关测试全部通过，无跳过，包含 CPU/CUDA：对照提交 `347f0cd` 中的旧求解器，覆盖不同事实数、float32/float64 求解与存储，Q 逐位一致；独立核对 HX=K、QH=Kᵀ、公式（6）的唯一最小值及事实排列；既有小模型的 R、最终权重、优化轨迹和接受/回退结果保持一致。共享范数与 H 的释放也已核对，未运行完整 8B 实验。测试继续仅保留本地。

## 候选网络与残差优化：功能、函数与公式

`candidate.py` 定义由 R 控制的真实候选网络，`optimize.py` 在该网络上计算目标与梯度，选择最佳 R。两者属于 P4；实际权重合并仍由 P5 完成。

核对结论：在当前常驻模型、合法目标层及 Q/R 精度一致的输入前提下，原实现和精简后的数学主线均与《最终逻辑 V1.0》第六、七节对齐。文档允许的保持训练选择中，本项目继续采用最初 theta_0 到候选模型的完整词表 KL；Adam、预算和检查点沿用既定配置。此处的最佳 R 是有限预算内的较优检查点，不表示整网全局最优。

| 公式/步骤 | 数学含义 | 实现对应 |
| --- | --- | --- |
| （2）（3） | $F=\sum_{i,t,j}w_{i,t,j}[-\log p_\theta(y_{i,j}\mid x_{i,t})]$ | 固定监督位置的交叉熵直接乘原全局权重求和，微批不重新平均 |
| （10） | $J(R)=F(\theta(R))+\beta L_{\mathrm{keep}}(\theta(R))+\tfrac12\sum_\ell\rho_\ell\lVert R_\ell\rVert_F^2$ | 编辑损失、可选完整词表 KL、逐层残差正则 |
| （11） | $z=(W_b+RQ)k+b=W_bk+b+R(Qk)$ | 在目标线性层的所有位置和每次实际调用上加入分支；偏置沿用基准输出 |
| （12） | $\nabla_{R_\ell}J=(\nabla_{\widetilde W_\ell}E)Q_\ell^\top+\rho_\ell R_\ell$ | 数据损失经过所有编辑层联合反传，每个完整优化步仅加一次正则梯度 |
| 有限步选择 | $R^{(0)}=0$，选择有限、非零且 $J(R^*)<J(0)$ 的最佳预定检查点 | 保留严格比较和原检查点顺序；无合格候选时返回 None |

## 实际合并与开发接受：功能、函数与公式

`merge.py` 把 P4 选中的 R* 和固定 Q 转成真实权重，`acceptance.py` 在实际合并模型上决定接受哪个公共 α，或恢复本轮基准。前者执行 P5 的写入和前向一致性，后者执行 P5 的开发选择；二者不承担独立生成评价。

核对《最终逻辑 V1.0》第八～十节及开发方案第八节：在常驻、非共享的目标线性层、形状/精度匹配、前向不额外修改参数的既定算法前提下，原实现与精简后的数学主线对齐。每个 α 都从 W_b 重建；不在上一试步权重上累加；R/Q 不改写，偏置不更新；因子分支关闭后才用实际权重前向。开发编辑的均分协议是文档允许、原代码已选定的具体实现，并非原文为所有算法唯一指定的协议。

不能把数学主线对齐理解成完整保留旧工程规范：历史文档中参数完整性摘要、共享存储扫描、辅助量诊断和阶段失败报告等要求，按当前精简方向不再在运行时执行；相应非法输入检查和异常包装行为已移除。

| 公式 | 数学内容 | 对应实现 |
| --- | --- | --- |
| （13） | $V_\ell^*=W_{b,\ell}K_\ell+R_\ell^*$，$\Delta W_\ell=R_\ell^*Q_\ell$ | 只计算真实增量 RQ；V* 是辅助定义，不写入参数 |
| （14） | $(W_{b,\ell}+\Delta W_\ell)K_\ell-V_\ell^*=R_\ell^*(Q_\ell K_\ell-I)$ | 参考键软拟合误差，可非零；原 diagnostics 仅计算其范数，未作为三门槛之一，现移到本地数学测试 |
| （11）（15） | $(W_b+\alpha RQ)k+b=W_bk+b+(\alpha R)(Qk)$ | 同输入、同 α 比较全部目标层每次调用的全位置输出及指定位置 logits |
| （15） | $W_{\alpha,\ell}=W_{b,\ell}+\alpha\Delta W_\ell$ | 所有层共用同一 α，沿用原分块乘法、加法次序和实际存储精度 |
| （16）（17） | $G_{\mathrm{dev}}=\sum_{h,j}b_{h,j}\sum_vp_{\theta_0,j}(v)\log\frac{p_{\theta_0,j}(v)}{p_{\theta_\alpha,j}(v)}$ | 完整词表 KL(theta_0 || theta_alpha)，即使训练 β=0 也执行 |
| （17） | $U=\frac{\sqrt{\sum_\ell\lVert W_\ell(\theta)-W_{0,\ell}\rVert_F^2}}{\max\{\sqrt{\sum_\ell\lVert W_{0,\ell}\rVert_F^2},\epsilon\}}$ | 用实际存储权重相对最初 W_0 的净差；保留原共同缩放、float64 分块范数及 hypot 累计 |
| （18） | $F_{\mathrm{dev}}\le F_{\mathrm{dev}}(\theta_b)-\delta$，$G_{\mathrm{dev}}\le\tau_G$，$U\le\tau_U$ | 三项分别判断，边界包含等号，不能互相抵消；依序接受首个全部通过的 α |

## LLaDA 适配器：模型计算与算法的连接

`model/adapters/llada_8b_instruct.py` 将 LLaDA 的真实 tokenizer、模型结构和前向调用接入 MDLM。它构造全 mask 短答案输入，捕获目标 FFN 输出线性层的实际输入，提供可微完整词表 logits，执行受控自主采样并保存内存轨迹，以及快照/恢复本轮目标权重。K/C 的组装、Q 求解、R 优化、实际合并和开发门槛仍在相应算法模块中。

### 与文档的对齐及范围

对照《最终逻辑 V1.0》3.1、公式（1）～（5）、（10）～（12）、（16）～（18）及 10.4，当前适配器在以下数据流上对齐：

- 输入采用真实 chat template 和主体/答案 token 对齐。目标答案只决定受控窗口长度并作为独立监督返回；采样参数不接收目标 token，也不回填答案。
- 自主采样只揭示现有 mask，不重新掩码；逐步保存前向前的独立输入及原精度 logits 摘要，终态单列。兼容筛选和三级监督权重仍由 states 完成。
- 公式（4）使用全 mask 初态、主体最后 token 的实际 `ff_out` 输入；公式（5）使用给定保持上下文和位置的同类实际输入。调用方负责 K 堆列、C 加权累计，捕获不进行归一化或去均值。
- 原位置读出完整词表 logits，不做自回归的 token 位置移位。`forward_logits` 保留候选计算图，支持多层 R 的梯度；捕获则使用 no_grad 并复制激活。
- 仅快照/恢复目标权重 W_b，保留原参数对象；固定 W₀ 参照由 runner 另存。未选层和偏置不由本文件写入。

这些结论限于当前 `block_group_size=1`、独立普通 `nn.Linear` 目标、全一 attention、连续隐式位置及受控短答案窗口。不能据此宣称所有扩散模型已适配，或已完成文档中的可选刷新和独立生成评价。文档规定自主、不重掩码及完整状态，并未唯一指定温度/置信度调度；当前调度是原代码已经选定的运行配方，本次沿用。实际模型源码和 8B 权重当前不在默认本地路径，真实大模型/RoPE 缓存验证未在本轮重跑。

### 直接数据对应及采样约定

公式（4）（5）中，本文件实际提供的是 k_ref 和 u，而非最终矩阵：

$$
K_\ell=[k_{1,\ell}^{ref},\ldots,k_{N,\ell}^{ref}],\qquad
C_\ell=\sum_m\omega_{\ell,m}u_{\ell,m}u_{\ell,m}^{\top}.
$$

可微前向在安装候选分支后支持公式（11）（12）：

$$
z=W_bk+b+R(Qk),\qquad
\nabla_RJ=(\nabla_{\widetilde W}E)Q^{\top}+\rho R.
$$

分支由 candidate 安装，梯度由 PyTorch 计算，损失与优化由 optimize 执行；适配器仅提供保留计算图的前向。完整词表读出还支持公式（16）（17）的 KL；snapshot/restore 则服务文档 10.4。公式（6）～（9）的求解、（13）（15）的合并和（18）的门槛判断没有移入本文件。

当前采样配方没有原算法编号：先对原精度 logits 计算摘要，再用 float32 副本将所有特殊 token 与 mask 标记置为负无穷。T>0 时按 softmax(logits/T) 使用专属种子生成器抽样；T=0 时取 argmax，置信度仍由 softmax(logits) 给出。每步按所选 token 的概率降序排列，概率相同时按原位置排序；若初始 M 个 mask 分 S 步揭示，第 s 步（从 0 起）数量为 floor(M/S)+1[s<M mod S]。所选位置按原索引顺序写回，之后只从剩余集合移除。该概率排除了特殊 token，不能替换公式（2）和 KL 所用的原始完整词表概率。

### 配方与公式的准确对应

对照《最终逻辑 V1.0》4.2、6.1、10.1～10.3，当前实现符合非负未中心化统计、保持训练/开发分开及完整词表 KL 的形式。文档要求具体保持语料、mask、位置、权重和开发编辑协议预先确定，没有唯一给出当前程序的具体配方，不能说本文件的所有选择均由原公式唯一推出。

对训练保持题 h，令 n_tr 为训练题数，A_h 为全 mask 答案位置，P_h={模板化提示末 token}∪A_h 为统计捕获位置。当前代码为每个目标层分配：

$$
\omega_{\ell,h,p}=\frac{s}{n_{\rm tr}|P_h|},\qquad
C_\ell=\sum_{h\in\mathrm{tr}}\sum_{p\in P_h}
\omega_{\ell,h,p}u_{\ell,h,p}u_{\ell,h,p}^{\top}.\qquad\text{原公式（5）}
$$

s 是 statistics_scale，默认 1；各目标层的统计权重总量为 s，不强制固定为 1。取的是实际目标 FFN 输入，累计仍由 keep_statistics 完成，不去均值。

对训练或开发保持分区 g，当前题/位置均分配方是：

$$
b^{g}_{h,j}=\frac{1}{n_g|A_h|},\qquad
\sum_{h\in g}\sum_{j\in A_h}b^{g}_{h,j}=1.
$$

这给公式（10）采用的 KL 保持项和公式（16）的开发保持项提供权重，KL 定义见公式（17）；本文件不计算概率、KL 或公式（17）的累计权重变化 U。这里的均分表达式是当前配方，不能误标成原公式（3）：公式（3）还包含事实/兼容状态/剩余 mask 的训练监督层级，本文件并不处理去噪状态。

## 主体与短答案对齐：输入定义与公式

`data/validation/alignment.py` 服务于 LLaDA 适配器的 `_prepare_short_answer`，编辑输入与开发编辑输入共用它。调用方先套真实聊天模板，本文件返回 `TokenAlignment`，再由适配器生成 `MaskedEditInput` 和单独的 `EditTarget`。保持统计/保持 KL 输入由 `encode_keep` 准备，不调用本文件。

### 类型与函数职责

| 名称 | 作用 |
| --- | --- |
| `AlignmentError(ValueError)` | 标识当前 tokenizer 无法建立主体位置或稳定短答案边界；保留原异常类型、提示及既定异常包装范围 |
| `TokenAlignment` | frozen 数据类，字段顺序保持为 prompt_ids、subject_positions、answer_ids，均为整数元组 |
| `TokenAlignment.subject_last_position` | 返回 subject_positions 的最后一个下标，供公式（4）的主体末 token 取键 |
| `align_edit_prompt(tokenizer, rendered_prompt, subject, answer)` | 定位唯一主体的 token 覆盖，核对提示前缀及答案解码，返回以上三个元组 |

对齐函数先要求三个字符串非空，并用两次 find 判断主体在整个模板化提示中唯一出现；第二次从第一次起点加一开始，因此重叠出现也会拒绝。随后调用 tokenizer 两次，均关闭 add_special_tokens：第一次取得提示 token 与 offset_mapping，第二次取得“提示+答案”的 token。offset 数须等于提示 token 数。

主体定位以字符区间相交为准：对主体区间 [s,e)，保留满足 r>l、r>s、l<e 的 token 偏移 [l,r)。用 cursor 累积核对主体全覆盖，核对左边界不后退、无覆盖缺口、不越出文本范围及 token 下标连续。字节级 token 可以共享字符偏移；token 也可以合并主体边缘的空格或邻接字符，本规则不要求 token 边界恰等于主体字符串边界，也不另外分词主体。

答案部分要求“提示+答案”的 token 前缀与提示完全相同，然后截取非空答案后缀；答案不得含 tokenizer 特殊 token。最后 decode 关闭 skip_special_tokens 与 clean_up_tokenization_spaces，结果须与原 answer 逐字相同。不会 strip、Unicode 归一化、补空格或猜测另一种可用边界。缺少 offset 支持时沿用原错误；本次未扩展 tokenizer 适配能力。

### 与数学文档的对应

对照《最终逻辑 V1.0》符号表、3.1～3.4、4.1 和开发方案 P0 的实际 tokenizer 对齐要求，本文件符合当前默认主线对主体位置、固定短答案位置及目标 token 的定义。下面是实现中的坐标关系，不是新增的原算法编号：令 T 为不额外添加特殊 token 的分词，p 为模板化提示，a 为答案，B=|T(p)|。代码要求

$$
T(p\Vert a)_{0:B}=T(p),\qquad
a^*=T(p\Vert a)_{B:},\qquad
\operatorname{decode}(a^*)=a.
$$

适配器据此建立

$$
\mathcal A_i=\{B,\ldots,B+|a^*|-1\},\qquad
x_{i,0}=T(p)\Vert[\mathrm{MASK}]^{|a^*|}.
$$

这给公式（1）的兼容比较、公式（2）（3）的逐位置监督提供 A_i 与 a*，不在本文件计算 T_i、损失或归一权重。目标内容只在准备阶段用于分词和监督，适配器传给采样器的是等长 mask 窗口。

令 p_i 为 subject_last_position，则公式（4）的后续提取使用

$$
k^{\mathrm{ref}}_{i,\ell}=k_{\ell,p_i}(x_{i,0};\theta_b),\qquad
K_\ell=[k^{\mathrm{ref}}_{1,\ell},\ldots,k^{\mathrm{ref}}_{N,\ell}].
$$

本文件只确定 p_i；实际 FFN 输入捕获与 K 堆叠由适配器和 extract_reference_keys 完成。开发编辑也复用同一对齐，提供公式（18）中 F_dev 所需输入；本文件不执行开发门槛。

唯一主体、连续完整的 offset 覆盖、稳定前缀和精确 decode 是当前输入构造规则，数学公式没有逐条唯一规定这些程序限制。部分可表达的自然语言题目会因重复主体或分词边界变化而拒绝；这里的“对齐”指当前支持输入满足算法坐标定义，不代表支持任意提示/tokenizer，也不承担事实审核或跨划分数据质量检查。提示已有 mask 的检查仍在适配器中。

## 已审核案例转换：事实集合与保持题归属

## JSON 案例读取：格式分派与用途标签

`data/readers/json_cases.py` 是数据集文件入口。runner 从配置 dataset 或命令行 --dataset 得到路径，调用 load_cases 后再选例、按源案例分组并准备保持输入。配置中的相对路径由 runner 按项目根解析；load_cases 本身只执行 Path(path)，不查找默认文件或修改源文件。
