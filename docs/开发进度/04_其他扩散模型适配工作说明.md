# 04 其他扩散模型适配工作说明

状态：适配规划，原始模型盘点于 2026-10-23，运行结构于 2026-10-28 更新。依据：[最终逻辑 V1.0](../最终逻辑%20V1.0.md)、[现行代码结构](../项目结构设计/00_当前代码结构与阅读顺序.md)及 `model/base.py`、`model/adapters/llada_8b_instruct.py`。本文件记录另外三个已下载模型要完成的适配工作；**下载完成不等于适配完成**。目前运行入口和最终模型加载仍使用 LLaDA 适配器，正式多事实、多层 8B 验收尚未完成。

## 1. 共同目标与边界

每个新模型先实现 P0/P1 的真实输入、前向和自主去噪接口；若要称为**完整知识编辑适配**，还须让同一模型贯通 P2 的目标 FFN 输出线性层输入捕获和 K/C、P3 固定 Q、P4 全位置候选梯度、P5 实际权重合并/开发门槛/回退/重载。P6 独立自由生成属于后续独立工作。各模型应分别确定模型路径、目标层、采样规则、精度及容差；当前算法流程通过内存对象衔接，不生成逐阶段文件摘要或版本清单。

继续沿用现有案例 JSON，读取时默认数据已在运行前审核；仓库不再提供独立的数据校验脚本。编辑目标 token 只留在监督侧，自主去噪和最终生成不接收目标答案。K 必须是本轮全 mask 初态、主体末 token、**实际被选 FFN 输出线性层的输入**；C 从同一目标的保持输入按原公式（5）累计。Q、R、合并和开发门槛维持现有公式，不因模型切换而默默改变数学定义。

以上是**本地配置、模型源码和权重索引的静态检查**，不是三个模型的真实加载或前向验收。尤其不能仅凭模块名称认定捕获点、精度、共享关系及可写性。三个模型配置所记 Transformers 版本分别为 4.46.2、4.57.1、4.53.2；当前项目环境以 LLaDA 的 4.38.2 为基线，需逐模型实测并记录兼容环境，必要时使用独立虚拟环境。

## 4. 建议实施顺序与验收门槛

1. **模型盘点**：逐模型固定权重/Tokenizer 摘要和环境；核对官方随附源码的加载类、模型输出、mask ID、模板、上下文长度和实际目标层。Dream、iLLaDA 可优先推进密集 FFN 路径；MoE 先验证路由和编辑目标的数学可行性。
2. **P0/P1 验收**：真实模型全 mask 前向与重复 logits、主体及答案位置、目标 FFN 输入捕获/权重方向正确；自主去噪在内存中保留每次前向前的独立输入快照，可按固定 seed 重放，过程中不回填答案。MoE 也可先达到此级别。
3. **P2/P3 验收**：K 的事实列和 C 的保持位置都对应相同的实际目标矩阵；形状、重放、数值 QA、Q 求解的双侧残差通过。MoE 必须先证明各目标专家的路由覆盖、缺席事实处理和统计定义符合明确的算法方案。
4. **P4/P5 验收**：真实候选网络的所有目标调用位置均有梯度；实际 `ΔW=RQ` 与因子候选前向在冻结容差内等价；按固定公共 α 顺序执行三个独立开发门槛；拒绝和异常可恢复，最终目标层权重可重载再前向。P5 失败不得误报为模型适配完成。
5. **正式完成口径**：每个模型分别留下 P0～P5 的单案例真实技术报告、代码测试和人工审核记录，再用正式已审核事实及多状态、多事实、多层配置完成阶段验收。P6 还要另外验证独立自由生成。任何一个模型的通过报告都不自动证明其他模型通过；一条人工构造案例不作为正式效果结果。

当前最需要先解决的是 **MoE 的编辑目标与公式（4）～（15）的对应关系**。在目标确定以前，密集模型的适配工作可以继续，MoE 的 P0/P1 接口也可以独立推进。
