# 当前项目的数据集读取逻辑

本文以当前代码为准，说明编辑入口如何读取和转换数据，以及 ZSRE、UltraEditBench、WikiBigEdit、FEVER 和项目原生案例的字段映射。这里的“读取”只负责构造文本案例与保持题；模型分词、主体定位、去噪、编辑和评分由后续模块处理。

## 1. 入口与数据流

1. `main.py` 将主配置交给 `MDLM/runner.py`。`util/io.py::read_config` 依次合并模型、数据集、算法子配置，最后用主配置的同名顶层字段覆盖。默认 `configs/main.json` 选择 `configs/datasets/cases.json`。
2. `MDLM/runner.py` 调用 `data/dataset.py::load_dataset`。它按 `dataset_reader` 选择读取器，返回 `DatasetBundle(cases, keep_pool, metadata)`。省略 `dataset_reader` 时使用 `native`。
3. `cases` 是已转换的事实列表。runner 先在读取范围内按 `case_ids` 选事实或源案例，再按 `source_case_id` 分组，最后以 `max_cases` 限制实际编辑的源案例组数。同一源案例下多个事实默认联合编辑。
4. `keep_pool` 是可选的独立保持题来源。配置 `keep_path` 时从该文件读取；未配置时为 `None`，`MDLM/states.py::prepare_inputs` 从**全部已读取案例**的 `prompts.preservation` 收集保持题。保持题来源不随 `case_ids`、`max_cases` 缩小。
5. `prepare_inputs` 按题目 `strip()` 后的摘要去重，保留首次出现的原始问题和答案；再用 `seed` 确定性排序，按 `keep_dev_fraction`、`keep_test_fraction` 划分开发、测试和统计训练保持题。测试分区目前只保留编号，不进入训练、候选选择或评价。

`source_limit` 限制编辑文件中**源记录**的前 N 条，发生在格式转换和选例之前；`keep_limit` 限制独立保持文件的读取量，发生在保持题去重之前。两者均要求正整数或 `null`。`keep_limit` 必须同时指定 `keep_path`。`max_cases` 只限制编辑组数，不减少 `load_dataset` 读取的案例范围。

配置里的 `dataset_path`、`keep_path`、FEVER 的 `subject_path` 相对项目根目录；命令行 `--dataset` 覆盖的路径相对当前工作目录，且只覆盖编辑源文件，不切换读取器或保持文件。`DatasetBundle.metadata` 记录读取器、路径、限量、案例数、读取参数、种子和保持题数，并写入运行报告的 `dataset_reading`。

## 2. 通用外部读取规则

四个外部读取器共用 `data/readers/base.py`：

- `.jsonl` 逐非空行解析，空行不计入源记录；其他后缀按 JSON 数组或单个对象读取，数组由 `ijson` 流式迭代。支持 UTF-8 BOM。达到 `source_limit` 后停止迭代，但已读取的案例仍汇成列表交给 runner。
- 保留文件原顺序，不随机抽样。每条外部源记录转换成一个编辑案例，默认不按主体合并。必需字段直接按键读取，缺字段或解析失败不自动跳过。
- 案例 ID 为 `<读取器>:<源文件名去后缀>:<原 case_id 或从 0 开始的源记录下标>`；`source_case_id` 与它相同。探针 ID 再追加 `:<用途>:<序号>`。读取范围内重复案例 ID 会报错。重命名源文件会改变 ID；没有原 `case_id` 时重排记录也会改变 ID。
- 每个案例的 `prompts` 包含 `edit`、`generalization`、`preservation`、`persona`、`portability`、`free_form_qa` 六组。编辑题的 `used_for_edit=true`；其他题为 `false`。额外题保留供独立评估使用，不自动加入编辑监督。
- 探针的 `prompt` 和 `answer` 必须是非空文本；读取器不 `strip` 实际文本、不追加答案空格，也不做分词。`fact_core.new_object` 取编辑目标；`subject`、`relation`、`old_object` 按各读取器映射。`metadata` 保留源文件、源下标、原始 ID 和主体缺失标记。
- 配置 `keep_path` 时，外部读取器只从其中每条记录取保持问题/答案，不要求该文件具有编辑、改写或多跳字段；每条源记录生成一道保持题。它使用同一个读取器的 ID 规则，且不会与编辑文件的记录合并。

## 3. 各数据集的字段映射

| 数据集 / 读取器 | 当前示例编辑文件、读取上限 | 编辑问题 → 目标答案 | 额外问题 | 保持问题 → 答案 |
| --- | --- | --- | --- | --- |
| ZSRE / `zsre` | `zsre_eval_20k.json`，前 20,000 条 | `src` → `ans`（可用 `target_field` 改为 `alt`） | `rephrase` → `generalization`，答案同编辑目标 | `loc + "?"` → `loc_ans` |
| UltraEditBench / `ultraeditbench` | `UltraEditBench_2M.json`，前 20,000 条 | `prompt` → `ans` | `rephrase_prompt` → `generalization` | `loc` → `loc_ans` |
| WikiBigEdit / `wikibigedit` | `wikibigedit_eval_17k.json`，前 17,000 条 | `update` → `ans` | `rephrase` → `generalization`；`personas` → `persona`；`mhop` → `mhop_ans` 为 `portability` | `loc` → `loc_ans` |
| FEVER / `fever` | `fever_eval_20k.json`，前 20,000 条 | `prompt` → `alt` | `equiv_prompt` → `generalization` | `unrel_prompt` → `unrel_ans` |

四个示例配置都把 `keep_limit` 设为 512，从各自训练文件前 512 条源记录提取独立保持题。文件名中的规模和读取上限只是当前配置值，不代表文件实际记录数。配置文件分别为 `configs/datasets/zsre.json`、`ultraeditbench.json`、`wikibigedit.json`、`fever.json`。

### ZSRE

`subject` 直接取源字段。`fact_core.old_object` 不从 `alt` 推断，保持为 `None`；`metadata` 保存 `original_ans`、`original_alt` 和实际 `target_field`。默认目标 `ans` 是当前配置的明确选择；若实验要把 `alt` 作为目标，应在 `reader_options.target_field` 指定。保持题会无条件给 `loc` 末尾追加一个问号，因此输入若已有问号也不会自动去重。

### UltraEditBench

`subject` 取源字段，`fact_core.old_object=None`。读取器记录目标字段为 `ans`。除 `rephrase_prompt` 和 `loc/loc_ans` 外，其他源字段不自动映射为探针。

### WikiBigEdit

`subject` 取源字段，`fact_core.old_object=None`，`metadata` 另存可选的 `tag`。`mhop` 和 `mhop_ans` 同时为 `null`、空字符串或字符串 `"null"` 时不生成多跳题；只缺其中一项会报错。两者均存在时以 `mhop_ans` 为多跳题答案，而非编辑目标 `ans`。

### FEVER

编辑目标固定为 `alt`，原 `ans` 存入 `fact_core.old_object`。主体优先取源记录的 `subject`；缺失时可从 `reader_options.subject_path` 指向的 JSON 对象按完整案例 ID 查找。若两处都有且不一致，读取时报错。主体仍缺失的案例可以被读入，但后续被实际选中编辑时，主体定位校验可能终止运行。

`equiv_prompt` 必须是非空字符串列表。`rephrase_policy=single_fixed`（默认）依据 `seed` 和案例 ID 的 SHA-256 摘要为每个案例确定性选一道改写题；`all` 则保留全部改写。选择不依赖读取顺序或全局随机状态。`subject_path` 的标注只用于编辑主体定位，不改变问题或答案字段。

## 4. 项目原生案例 `native`

默认数据配置 `configs/datasets/cases.json` 指向 `data/datasets/cases.jsonl`，未显式指定读取器，因此走 `native`。它支持两种输入：

1. **已是运行时案例**：JSON 对象、JSON 数组或 JSONL 各行的案例直接保留原字段与原顺序，不重建探针。运行时至少需要 `case_id`、`prompts.edit` 等后续模块使用的字段。
2. **审核源格式**：首条记录同时有 `edit_requests` 和 `edit_questions` 时，整份数据按 `adapt_reviewed_cases` 转换。只保留 `gold_ready` 为真的源案例；每个请求与同下标编辑题配对并展开为一个事实。单请求事实用源 `case_id`，多请求事实用各 `request_id`；都保留 `source_case_id`，以便 runner 联合编辑。编辑答案取 `expected_new_answer`，事实核中的新对象取请求的 `experimental_new_answer`。`preservation_questions` 只挂在首个展开事实下，避免同源重复。未映射的额外评价题不会被自动生成。

原生 `source_limit` 同样按展开前源记录计数。未设置限量时，`load_cases` 一次加载完整 JSON/JSONL；设置限量时通过通用 `iter_records` 读取前 N 条。若 `keep_path` 指定另一份原生案例文件，会从其中所有案例的 `prompts.preservation` 按原顺序展开，并以 `keep_limit` 限制**题目数**，不是源记录数。原生读取器不接受 `reader_options`。

可选转换命令 `python -m data.dataset <审核源.jsonl> <输出.json或jsonl> [--case-id ID]` 将审核源转换后写入新文件；正常运行 `main.py` 不需要预先转换，也不会改写数据集文件。

## 5. 评估时如何重读

`evaluation/artifacts.py::read_evaluation_data` 从已完成编辑的 `run_report.json` 恢复 `dataset_reader`、编辑源路径、`source_limit`、读取参数和读取种子，再调用同一个 `load_dataset`。它核对重读后的案例数，仅评价报告中实际尝试的事实。评估不重读编辑保持池；FEVER 的 `subject_path` 会被移除，因为评估文本题目和答案无需主体标注。评估命令的 `--dataset` 仅用于源文件搬迁后的路径覆盖；改文件名可能改变外部案例 ID。

## 6. 快速检查

先在 `configs/main.json` 中把 `dataset_config` 改成所需的 `datasets/*.json`，然后无需加载模型即可查看读取结果：

```python
from pathlib import Path
from data.dataset import load_dataset
from util.io import read_config

bundle = load_dataset(read_config(Path("configs/main.json")))
print(bundle.metadata)
print(bundle.cases[0]["case_id"], bundle.cases[0]["fact_core"])
print("keep probes:", None if bundle.keep_pool is None else len(bundle.keep_pool))
```

具体入口和映射见 `data/dataset.py`、`data/readers/*.py`；保持划分见 `MDLM/states.py::prepare_inputs`；选例分组见 `MDLM/runner.py::select_cases`；配置项总览见 `docs/配置参数说明.md`。
