# 当前项目的数据集读取逻辑

项目仅保留原生 cases 数据集。配置文件是 `configs/datasets/cases.json`，默认数据文件是 `data/datasets/cases.jsonl`，二者分别负责参数与案例内容。原先导入的四类外部数据及其专用读取器已移除。

## 入口与数据流

`main.py → MDLM/runner.py → data/dataset.py::load_dataset → load_cases`。

`configs/main.json` 通过 dataset_config 引用 cases 配置。资源路径相对项目根目录；命令行 --dataset 可以覆盖为另一份原生 cases 文件，路径相对当前工作目录。

load_cases 使用标准库读取 JSON/JSONL，支持 UTF-8 BOM。JSON 可以是单个对象或对象数组；JSONL 按非空行读取，保留文件顺序和原始文本。普通运行时案例原样返回；首条同时包含 edit_requests 和 edit_questions 时，整份源数据调用 adapt_reviewed_cases。

load_dataset 返回 DatasetBundle(cases, keep_pool, metadata)。这个返回接口继续供编辑入口及现有调用方使用；不再注册或分派外部读取器。旧配置若指定非 native 的读取器或非空 reader_options，会明确终止，避免用错误格式继续实验。

## 审核源格式的转换

只保留 gold_ready 为真的源案例。每个 edit_requests 与同下标 edit_questions 配对，展开为一个事实；两组长度必须一致。

- 单请求事实沿用源 case_id；多请求事实使用各 request_id。
- 每个事实保留共同的 source_case_id，runner 据此将同一源案例的事实联合编辑。
- 编辑题的 prompt 取 question，监督答案取 expected_new_answer。
- fact_core 保留请求的 subject、relation、old_answer、experimental_new_answer。
- preservation_questions 转换为保持题，只挂在首个展开事实下，避免同源重复。
- 原有转换不映射独立测试题，free_form_qa、portability 仍为空。

以上规则不修改源文件，也不重新判断人工审核结论。

## 读取范围与保持题

source_limit 可设为正整数或 null，按展开前源记录限量；默认读取全部。JSONL 可在限量后停止解析，JSON 数组由标准库整体解析后取前 N 条。

runner 在已读取案例中先用 case_ids 选例，再按源案例分组，以 max_cases 限制实际编辑组数。这两项不缩小默认保持题来源。保持题由 MDLM/states.py::prepare_inputs 从全部已读取案例的 prompts.preservation 收集、去重，并用 seed 固定排序和划分。

原生格式仍支持可选 keep_path，从另一份原生 cases 文件的 preservation 组取保持题；keep_limit 按题目数限量，必须同时指定 keep_path。默认配置不使用独立保持文件。

主体定位、答案 token 对齐、全 mask 输入构造和模型前向由后续模块执行。数据读取不做模型分词。

## 启动与只读检查

```bash
python -u main.py --config configs/main.json
```

无需加载模型即可检查读取数量：

```python
from pathlib import Path
from data.dataset import load_dataset
from util.io import read_config

bundle = load_dataset(read_config(Path("configs/main.json")))
print(bundle.metadata)
print([case["case_id"] for case in bundle.cases])
```

可选转换命令 `python -m data.dataset <审核源.jsonl> <输出.json或jsonl> [--case-id ID]` 会写入指定输出文件；正常编辑直接在内存中转换，无需预先执行该命令。
