# MDLM 配置参数说明

`main.py` 默认读取 [main.json](../configs/main.json)，再组合模型、数据集和算法配置。精度统一使用代码默认值；JSON 不支持注释，修改时参考本文。

## 配置文件分工

| 文件 | 保存内容 |
| --- | --- |
| [main.json](../configs/main.json) | 算法、统一种子、编辑模式、选例范围、三个配置引用和输出位置 |
| [models/llada_8b_instruct.json](../configs/models/llada_8b_instruct.json) | `model_path`、`target_layers` 和 `execution`，确定模型、编辑层及设备 |
| [datasets/cases.json](../configs/datasets/cases.json) | 平铺的 `dataset_path`、保持划分比例和统计权重尺度 |
| [editors/mdlm.json](../configs/editors/mdlm.json) | 直接按名称设置 MDLM 的采样、求解、优化和合并参数，无阶段编号分组 |

`cases.json` 沿用现有数据路径命名，尚未假定具体数据集种类。更换数据集时可新增对应 JSON，再修改 `main.json` 的 `dataset_config`。

三个 `*_config` 路径相对主配置所在目录；`dataset_path`、`model_path` 和 `output_root` 等资源路径仍相对项目根目录。各子配置按上述职责保存参数，不重复定义。读取时按模型 → 数据集 → 算法的顺序合并顶层字段，最后主配置的同名顶层字段优先；嵌套对象不递归合并。

## 实验模式与范围：`main.json`

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `mode` | `independent` | 每个源案例从原模型开始；`sequential` 则接续已接受的模型，拒绝后继续后续案例 |
| `max_cases` | `null` | 最多编辑的源案例数；正整数按数据集顺序取前 N 组，null 表示不限量 |
| `case_ids` | `null` | 指定源案例或事实编号列表，null/空列表表示全部；列表顺序不改变数据集顺序 |

先按 `case_ids` 筛选，再按源案例分组和 `max_cases` 限量。选源案例时包含其全部事实；显式选事实编号时仅编辑所选事实。一个源案例可有多个事实，因此 max_cases 不是事实数或优化微批大小。

命令行 `--mode`、`--max-cases` 和 `--case-id` 分别优先于这三项配置；`--case-id` 替换配置列表，而不是追加。只限制编辑对象，保持输入始终由完整数据集准备。

## 统一随机种子

只需修改 `configs/main.json` 的 `seed`，当前为 `2026`。runner 将同一个值传给保持输入划分、轨迹采样和残差优化，并记录到 `run_report.json`；未填写时沿用 `2026`。子配置不再包含 `sampling_seed`、`optimization_seed` 或输入划分种子。

保持题仍按种子与题目摘要排序；轨迹仍结合统一种子与事实/探针编号派生各自种子；优化开始时用统一种子设置 PyTorch。改变主种子会同时影响这些环节，独立/连续编辑的执行方式不变。

## 启动与常用修改

```bash
conda activate mdlm
python -u main.py --editor mdlm
# 显式指定主配置，与默认启动等价
python -u main.py --config configs/main.json
```

首次使用先修改数据配置中的 `dataset_path`、模型配置中的 `model_path`，再确认 `execution.device`、`target_layers` 和主配置中的实验模式/范围。算法名来自主配置 `editor`，也可用 `--editor` 覆盖。

```bash
# 临时覆盖配置中的路径和设备；命令行路径相对当前目录
python -u main.py --editor mdlm --dataset data/datasets/cases.jsonl --model-path model/models/LLaDA-8B-Instruct --device cuda:0

# 只编辑指定源案例/事实，另取一个输出目录名
python -u main.py --editor mdlm --case-id cf_00001 --run-id trial_01

# 连续编辑：后续源案例接续已接受的模型
python -u main.py --mode sequential --max-cases 10

# 临时改回独立编辑；--sequential 和位置参数 sequential 仍兼容
python -u main.py --mode independent
```

默认按源案例独立编辑，同源所选事实联合编辑。`--case-id` 可重复指定；它与 `--max-cases` 均不改变保持输入划分。输出目录名默认自动生成，也可用 `--run-id` 指定一个未使用的单层目录名。

## 路径、层与设备

| 参数 | 当前值 | 作用 |
| --- | --- | --- |
| `dataset_path` | `data/datasets/cases.jsonl` | 输入案例文件，支持 JSON/JSONL；审核源格式由读取器自动转换 |
| `model_path` | `model/models/LLaDA-8B-Instruct` | 本地模型与 tokenizer 目录 |
| `output_root` | `runs` | 保存运行摘要、接受后的最终目标权重和模型元数据 |
| `target_layers` | `[0]` | 待编辑的 Transformer 层编号，从 0 开始；列表顺序也决定逐层处理顺序 |
| `execution.backend` | `resident` | 沿用驻留模式精度：关闭矩阵乘法和 cuDNN TF32，退出后恢复；当前流程统一为单进程 |
| `execution.device` | `cuda:0` | 模型、C 累计、Q 求解的统一设备；可改为 `cpu`，命令行 `--device` 优先 |

`resident + cuda:*` 会自动启用等长保持输入分批；CPU 下逐条处理。设备只在模型配置中设置，模型、C 累计和 Q 求解统一使用。

模型配置只需修改 `target_layers`；具体模块名由模型适配器按层序生成，算法配置无需填写 LLaDA 模块名。`ridge` 和 `rho` 为标量时用于全部目标层；需要逐层设置时填写与 `target_layers` 等长且同序的列表。例如层为 `[0, 1]`，`ridge: [0.01, 0.02]` 分别对应第 0、1 层。列表长度不匹配会报错；具体数值由实验确定。

## 数据与保持输入：`datasets/cases.json`

未指定 `keep_path` 时，从完整已读取案例集的 `preservation` 题准备保持输入；指定后使用该文件提供的独立保持池。两种来源均按原题目摘要去重并固定分区。统计 C 与可选保持训练共用训练分区；开发保持使用开发分区。

| 参数 | 当前值 | 作用 |
| --- | --- | --- |
| `keep_dev_fraction` | `0.25` | 开发保持题比例；需大于 0，用于编辑后的保持验收 |
| `keep_test_fraction` | `0.25` | 额外留出保持题比例；当前只保留划分，不编码或执行评价 |
| `statistics_scale` | `1.0` | 公式（5）中 C 的位置权重总尺度；需大于 0，会影响 Q |

排序与划分使用主配置的 `seed`，无需在本节设置。两个比例各在 `[0, 1)` 且和小于 1；至少需要两道去重后的保持题。小数据按原计数规则截断/限幅，至少保留一条开发题和一条训练题，test 可能为空。保持分区互斥不代表编辑开发题独立留出。

留出保持题是为了避免只在参与约束的数据上判断知识是否保持。以 100 道去重保持题为例：50 道用于 C 统计及可选保持训练；25 道开发保持题不参与这些计算，用完整词表 KL 检查编辑后的输出分布变化，参与接受/拒绝；另 25 道不参与训练和候选选择，预留给后续独立检验，当前不执行评价。β=0 时仍使用 C 和开发保持门槛。

以上是保持题划分，不是编辑事实划分。开发编辑继续使用代码默认的 edit 探针，不在 JSON 中暴露只支持一个值的策略字段；原输入准备函数的内部参数和计算保持不变。

## 可选数据读取器

主配置的 `dataset_config` 可以选择 `datasets/cases.json`、`datasets/zsre.json`、`datasets/ultraeditbench.json`、`datasets/wikibigedit.json` 或 `datasets/fever.json`。默认仍为 cases；切换数据源不需要修改算法配置。新增示例配置使用本地 `data/datasets/ultraedit/` 中的文件，读取器不下载、不修改、不回写原始数据集。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `dataset_reader` | `native` | `native`、`zsre`、`ultraeditbench`、`wikibigedit`、`fever` 中的一种；显式选择，不猜测外部格式 |
| `dataset_path` | 沿用数据配置 | 编辑源文件；配置中的资源路径相对项目根目录 |
| `source_limit` | `null` | 按文件原顺序读取前 N 条源记录；正整数或 null，null 表示全部。原生审核源按展开前记录计数 |
| `keep_path` | `null` | 可选独立保持来源，使用相同读取器的无关问题字段；native 从该文件的 preservation 组取题 |
| `keep_limit` | `null` | 独立保持池的读取上限，必须与 keep_path 同时使用；在去重前限量。外部格式一条源记录对应一道保持题，native 按展开后的 preservation 题计数 |
| `reader_options` | `{}` | 对应读取器的参数；未知参数报错，native 不接受额外读取参数 |

外部 JSON 数组通过 `ijson` 流式解析，JSONL 逐行读取，同时支持单个 JSON 对象和 UTF-8 BOM。配置有限量时只构造前 N 条案例；解析器可能预读一小段缓冲区，不会加载整个大数组。最终已选读取范围仍物化为列表供现有 runner 使用，因此读取全部百万级记录仍需要相应内存。本次没有增加按轮加载、自动补样或调度机制。

`source_limit` 定义本次可选的源记录范围，`case_ids` 在这个范围内选例，`max_cases` 再限制实际编辑的源案例数。仅设置 `max_cases` 不会缩小读取范围。`case_ids`/`max_cases` 均不改变保持池；未指定 `keep_path` 时，修改 `source_limit` 会改变默认保持题来源。外部示例配置限制读取 20,000 条（WikiBigEdit 为 17,000 条），独立保持池取训练文件前 512 条；这些是控制首次接入规模的示例值，不表示文件真实总条数、最佳实验规模或随机抽样。需要全量时显式把 `source_limit` 设为 null。

| 读取器 | 编辑问题 / 目标答案 | 额外保留的问题 |
| --- | --- | --- |
| zsre | src / ans；可通过 `reader_options.target_field: "alt"` 切换目标 | rephrase → generalization；loc + `?` / loc_ans → preservation，沿用 UltraEdit 的拼接规则 |
| ultraeditbench | prompt / ans | rephrase_prompt → generalization；loc / loc_ans → preservation |
| wikibigedit | update / ans | rephrase → generalization；personas → persona；loc / loc_ans → preservation；mhop / mhop_ans → portability |
| fever | prompt / alt，原 ans 只作为 old_object 记录 | equiv_prompt → generalization；unrel_prompt / unrel_ans → preservation |

读取器复用 UltraEdit 的字段语义，不引入其自回归 token 拼接和 labels 构造。文本保持原样，不为答案添加前导空格；聊天模板、主体 token 定位和全 mask 答案窗口仍由原 MDLM 输入代码负责。ZSRE 默认 ans 是兼容 UltraEdit 的选择，不应把 alt 自动当作 ans 的旧答案；运行前应按自己的实验目标明确选择字段。

辅助问题仅作为文本保留，`used_for_edit=false`；不会自动加入编辑监督或替换现有开发编辑题。WikiBigEdit 多跳问题及答案同时缺失（null、空字符串或字符串 `"null"`）时不生成探针，只缺一项时明确报错。所有外部记录默认一条对应一个源案例，不按主体合并。

外部案例 ID 为 `<读取器>:<文件名去掉后缀>:<原 case_id 或从零开始的记录下标>`，probe ID 在其后附加用途和序号。原始 ID、文件路径和源下标保存在 metadata；读取范围内重复案例 ID、缺少必要文本或错误字段类型会报错，不自动跳过。移动文件到其他目录不改变 ID，重命名文件或重排没有原 ID 的记录会改变 ID；JSONL 的空行不计作源记录。

FEVER 原始数据缺少主体，而 MDLM 取键需要明确的主体位置，可用 subject_path 提供独立标注。编辑前检查主体唯一性、token 偏移覆盖、答案稳定前缀及精确解码；歧义或缺失时记录 failed 并非零退出，不能猜测位置。UltraEditBench 等数据中的歧义记录也遵循此规则；读取器不修改原文件。

FEVER 可在独立的标注文件中提供主体，无需修改原始数据集。文件内容例如：

```json
{
  "fever:fever_eval_20k:0": "需要人工确认、且在原问题中唯一出现的主体"
}
```

把该文件路径填入 FEVER 配置的 `reader_options.subject_path`；只需覆盖实际选中的案例，原记录已有 subject 时二者必须一致。上述文字是格式占位，不能直接用于实验。`reader_options.rephrase_policy` 默认 `single_fixed`，根据主配置 seed 与案例 ID 确定性选一个改写，不消耗全局随机状态；`all` 则保留全部改写。两种策略均不执行改写评价。

可先单独检查读取结果，不加载模型：

```python
from pathlib import Path
from data.dataset import load_dataset
from util.io import read_config

config = read_config(Path("configs/main.json"))
bundle = load_dataset(config)
print(bundle.metadata)
print(bundle.cases[0]["case_id"], bundle.cases[0]["fact_core"])
```

例如将主配置的 dataset_config 设为 `datasets/zsre.json` 后，可执行 `python -u main.py --config configs/main.json --max-cases 1`。`--dataset` 仅覆盖源文件路径，不切换读取器或保持来源。运行摘要的 `dataset_reading` 保存读取器、资源路径、限量、读取数量、参数和种子；不会生成转换后的数据文件。

独立 `keep_path` 只明确题目来源，其去重、划分和权重仍用原算法，不保证编辑集与保持集在语义上无重叠。自备数据可继续用 native 标准案例保留自定义的 free_form_qa 等字段；原审核源转换器的既有字段映射保持原样，不自动转换未知评价题结构。以后添加读取器时，在 `data/readers/` 实现文本映射并登记到 `data.dataset.READERS` 即可，短答案编辑与长答案评价的具体框架留待后续接入。

## 算法参数：轨迹采样

以下算法参数均直接位于 `editors/mdlm.json` 顶层。原来的 `p1`～`p5` 嵌套配置已移除，采样和优化共用主配置的 `seed`。

| 参数 | 当前值 | 作用 |
| --- | --- | --- |
| `denoise_steps` | `null` | 自动取答案 mask 数作为去噪步数；也可指定正整数，与残差优化步数 optimization_steps 不同 |
| `temperature` | `0.0` | 0 时按最大概率选 token，正数时按温度分布采样 |
采集前用两次相同输入前向核对 P0 一致性；replay_count 默认 1，按逐事实种子抽查轨迹重放，可设为 0，且不超过本轮事实数。采样输入不回填目标答案，目标仅用于随后监督。

## 算法参数：参考键与保持统计

K 从每事实的全 mask 初态提取，核对两次捕获及采样时的 logits 摘要。key_replay_atol/key_replay_rtol 默认 0.01/0.001，控制 K 重放及保存精度的容差。K 的列序、取键位置和存储精度保持原样。C 累计使用代码默认精度，设备和分批由模型配置决定，K/C 在内存中传递。

## 算法参数：固定因子求解

| 参数 | 当前值 | 作用 |
| --- | --- | --- |
| `ridge` | `0.01` | 目标层的 λ，标量或逐层列表；构造 `H = C + KKᵀ + λI`，λ 应大于 0 |

运行时将 λ 对应到适配器给出的目标模块，内部仍使用 `ridge_by_layer`，不改变求解器或系数。求解器固定为 Cholesky，对应公式（6）～（9）。

## 算法参数：残差优化

| 参数 | 当前值 | 作用 |
| --- | --- | --- |
| `rho` | `0.001` | 各层残差正则系数 ρ，标量或逐层列表；作用于 `Σ(ρ/2)‖R‖²`，与求解 Q 时的 λ 不同 |
| `beta` | `0.0` | 公式（10）中保持 KL 损失系数；0 时不做保持训练，开发保持验收仍执行 |
| `learning_rate` | `0.01` | Adam 学习率 |
| `optimization_steps` | `20` | 每轮残差优化步数，内部对应 max_steps |
| `selection_steps` | `[1, 5, 10, 20]` | 仅在这些优化步检查和选择候选；修改 optimization_steps 时同步安排有效步数，不保存磁盘检查点 |
| `microbatch_size` | `1` | 每次累计梯度的样本组大小；一个优化步仍遍历全部固定训练样本 |

运行时将 ρ 对应到目标模块，内部仍使用 `rho_by_layer`。R 从零开始，Q 与基准权重固定；候选从检查点中选取有限、非零且优于 `J(0)` 的最佳 R。优化器固定为 Adam，对应公式（10）～（12），其种子由 runner 从主配置统一传入。

## 算法参数：合并与接受

| 参数 | 当前值 | 作用 |
| --- | --- | --- |
| `alphas` | `[1.0, 0.5, 0.25]` | 按给定顺序尝试公共步长 α，接受首个通过者；各层共用 α |
| `delta` | `0.001` | 开发编辑损失至少改善 δ；越大越严格 |
| `tau_g` | `0.05` | 开发保持完整词表 KL 上限；越小越严格 |
| `tau_u` | `0.05` | 全部目标层相对最初 W₀ 的整体累计变化比例上限；越小越严格 |
| `epsilon` | `1e-12` | 公式（17）中相对范数分母的最小值 |
| `equivalence_atol` | `0.125` | 同 α 因子前向与实际合并前向的绝对误差容差 |
| `equivalence_rtol` | `0.02` | 上述前向一致性比较的相对误差容差 |
| `chunk_size` | `256` | 增量乘法、写回和累计变化计算的列分块大小 |

先核对同 α 前向一致性，再按公式（18）同时满足 `F_dev ≤ F_dev(W_b)−delta`、`G_dev ≤ tau_g`、`U ≤ tau_u` 才接受；每次从 W_b 重建试步，全部失败则恢复。`tau_u=0.05` 表示整体范数比例最多 5%，并非每个参数最多变化 5%。

当前配置沿用已有实验设置；更改保持划分、λ/ρ、β、检查点或接受门槛会改变实验定义，应在比较实验前固定。

## 代码默认精度（无需在 JSON 中填写）

| 阶段 | 当前代码默认行为 |
| --- | --- |
| 原模型 | runner 传入 `torch_dtype="auto"`；实际 dtype 取决于本地模型和加载器，不能固定视为 float32 |
| K/C | K 输出 float32；C 用 float64 累计后输出 float32 |
| Q | float64 Cholesky 求解，结果转 float32 并返回 CPU，使用时再移至目标设备 |
| R 与损失 | R/候选分支用 float32，分支结果转回原层输出精度再相加；半精度 logits 转 float32 计算 CE/KL，float64 logits 保留 float64；正则项用 float64 归约 |
| 合并与接受 | RQ/基准加增量用 float32 计算，再转回模型权重 dtype；累计变化 U 用 float64 归约 |

删除配置中的精度字段不会取消这些转换。`execution.backend=resident` 仍关闭 TF32；本次没有改变代码中的默认精度。

截至 2026-10-29，对照官方实现得到的结论是：分阶段使用精度的思路一致，但不存在跨算法统一的 dtype 标准，不能宣称与所有方法逐项相同。

- ROME 的 [GPT-J 配置](https://github.com/kmeng01/rome/blob/main/hparams/ROME/EleutherAI_gpt-j-6B.json)使用 float32 二阶统计，其 [compute_u](https://github.com/kmeng01/rome/blob/main/rome/compute_u.py) 将逆统计矩阵转回 float32。本项目 C 的 float64 累计是不同的数值选择。
- MEMIT 的 [更新求解](https://github.com/kmeng01/memit/blob/main/memit/memit_main.py)显式转 double 后求解，并在写回前将更新转 float32。本项目同样用 float64 求 Q、float32 写回，但 Q 先转 float32、后与 R 相乘，和 MEMIT 保留 double 因子的顺序不完全相同。
- AlphaEdit 的 [更新求解](https://github.com/jianghoucheng/AlphaEdit/blob/main/AlphaEdit/AlphaEdit_main.py)没有 MEMIT 同样的 double 转换，正则单位阵为 float32，其 [Llama3 配置](https://github.com/jianghoucheng/AlphaEdit/blob/main/hparams/AlphaEdit/Llama3-8B.json)也使用 float32 统计。因此不能为“对齐”而把所有模块统一成 float64 或 float32。

本次是源码设置对照；使用不同模型、加载 dtype 或硬件时，仍不能据此断言数值结果等价。现有默认设置保留，未替换 MDLM 的数值计算方式。
