# MDLM 标准答案回填评价方案：先预测、先评分，再回填

**文档状态：已实现，协议名 diffusion_gold_v1。** 实现位于 evaluation/inference.py，统一配置为 configs/evaluation/mdlm_ultraedit.json，通过 `protocol` 选择评价协议。diffusion_short_v1 仍将模型预测写入下一轮输入并在完成后评分。本文说明回填协议的流程、数学定义和实现边界。

## 1. 先理解这套评价在做什么

对一道题，先把答案区域全部设为 mask。每轮让模型预测所有剩余 mask，按照置信度选出本轮要评价的位置，记录这些位置预测得对不对；然后，无论刚才预测正确还是错误，都将所选位置写成标准答案 token，再进行下一轮。

**预测值负责评分，标准答案负责构造下一轮输入。两者必须分别保存。**

例如某位置标准答案为 B，模型预测为 X：这次预测记为错误，评分记录始终保留 X；但下一轮模型看到该位置为 B。回填不会把刚才的错误改成正确，只会改变后续预测的输入。

这套方案测量的是：**当已经评价过的位置都提供正确 token 时，模型能否预测剩余位置。** 它借鉴了 UltraEdit 使用正确上下文、避免预测错误进入后续输入的思想。

### 一道题的流程总览

~~~mermaid
flowchart TD
    A[读取问题和标准答案，建立答案 token 对齐] --> B[问题保持不变，答案区域全部设为 mask]
    B --> C[用当前输入前向计算，预测所有剩余 mask]
    C --> D[按候选预测的置信度选择本轮位置]
    D --> E[保存所选位置的预测，与标准 token 比较并记录对错]
    E --> F[统一将本轮所选位置写成标准 token]
    F --> G{是否还有未评价位置？}
    G -->|有| C
    G -->|无| H[根据保存的预测和对错，计算单题 token 正确率]
~~~

## 2. 始终分清三份数据

设标准答案有三个 token：[A, B, C]。

| 数据 | 用途 | 初始内容 | 何时改变 |
| --- | --- | --- | --- |
| 标准答案 target | 提供评分标签和回填值 | [A, B, C] | 全程只读 |
| 模型输入 state | 送给模型，决定下一轮预测条件 | [MASK, MASK, MASK] | 评分后，将本轮所选位置写成标准 token |
| 评分预测 scored_predictions | 保存模型在各位置被选中时的真实预测 | [空, 空, 空] | 每个位置只写入一次，之后不覆盖 |

这里 state 只展示答案区域，实际模型输入还包含前面的完整问题提示。

每个位置还有一条对错记录 correct[i]。预测正确为 1，错误为 0；回填之后不重新评分，也不覆盖这条记录。

尚未选中的位置即使本轮已有候选预测，也继续保持 mask。其候选预测可以用于日志，但不进入最终评分；下一轮需要基于新的输入重新预测。

## 3. 开始评价前，准备什么

对一道题，准备以下内容：

1. **问题提示**：用当前 LLaDA 聊天模板渲染问题，分词为提示序列 \(p\)。
2. **标准答案**：对“渲染后的提示 + 标准答案”分词，验证提示 token 是稳定前缀，取答案部分为 \(y=(y_1,\ldots,y_L)\)。
3. **有效输入约定**：要求 \(L>0\)，分词和解码精确对应标准答案，标准答案使用普通 token，输入不超过模型上下文；不自动截断。实现主动检查这些必要约束；不满足时使用 sys.exit(原因)，运行器保存 failed 报告并非零退出。文件、字段及张量运算错误沿用底层库原生异常，不使用 raise/assert。
4. **初始输入**：问题提示不变，后接恰好 \(L\) 个 mask。评分预测与对错记录均为空。
5. **运行配置**：确定温度、轮数、随机种子、模型权重和协议名称，并写入评价记录。

标准答案可以由评价程序持有，但模型只能看到问题、已评价位置的标准 token 和剩余 mask。**某位置在完成自己的评分前，不能把该位置的标准 token 放进模型输入。** 答案长度 \(L\) 已用于确定窗口，因此这是已知答案长度的条件评价。

主实验建议固定温度 \(T=0\)，每个位置取最大 logit 对应的 token，与原版 UltraEdit 的确定性预测方式一致。\(T>0\) 的抽样方式可以保留为扩展设置，但结果应单独标注，并通过多个种子观察波动。

## 4. 每一轮严格执行这五步

### 第一步：用当前输入预测所有剩余 mask

当前输入中，已经评价过的位置都是标准 token，尚未评价的位置都是 mask。

对当前输入进行一次模型前向，取得所有剩余位置的 logits。沿用当前 MDLM 的候选 token 约束，屏蔽特殊 token 和 mask token，然后为每个剩余位置确定候选预测及其置信度。

在默认 \(T=0\) 时：候选预测取最大 logit 对应的 token；置信度取该候选 token 在屏蔽后 softmax 分布中的概率。

### 第二步：按置信度选择本轮要评价的位置

按候选预测的置信度从高到低选择本轮位置。若置信度相同，按答案位置从小到大打破平局。不要求从左到右。

默认每轮只选一个位置。如果配置为每轮选多个位置，则先一次性确定本轮完整的位置集合。

选位使用的是**候选预测 token 的概率**，不能使用标准答案 token 的概率、是否预测正确等标签信息来决定位置。

### 第三步：先保存预测，再比较并记分

只对本轮选中的位置执行：

- 将候选预测写入 scored_predictions[i]。
- 将预测 token ID 与 target[i] 比较，记录 correct[i]。
- 保存本轮位置、预测、置信度、标准 token 和对错，供后续核查。

**这一步完成前，模型输入不发生任何回填。**

### 第四步：统一回填本轮位置的标准 token

对本轮所有选中位置，执行 state[i] = target[i]。预测正确和预测错误的位置都这样处理。

回填只更新模型输入，不修改 scored_predictions 和 correct。随后从“未评价位置集合”中移除本轮位置。

同轮多个位置基于同一次、回填前的前向结果评分。不能评分一个位置就立刻回填并重新前向，再评分同轮另一个位置；那会改变同轮各位置获得的条件。

### 第五步：检查是否结束

如果还有未评价位置，使用回填后的输入开始下一轮；如果所有位置均已评价，则停止模型预测，根据保存的评分记录计算单题分数。

已经评价过的位置不再选中、不再评分，也不重新预测。

## 5. 看一个完整的三轮例子

假设标准答案为 [A, B, C]，每轮选一个位置。下面的置信度仅用于说明流程，具体数值由模型计算。

| 轮次 | 本轮模型看到的答案区域 | 所有剩余位置的候选预测及置信度 | 本轮选位 | 先保存预测并评分 | 再回填后的答案区域 |
| --- | --- | --- | --- | --- | --- |
| 1 | [MASK, MASK, MASK] | 位置1：D / 0.40；位置2：X / 0.90；位置3：C / 0.60 | 位置2 | X ≠ B，记0 | [MASK, B, MASK] |
| 2 | [MASK, B, MASK] | 位置1：A / 0.85；位置3：Z / 0.70 | 位置1 | A = A，记1 | [A, B, MASK] |
| 3 | [A, B, MASK] | 位置3：C / 0.95 | 位置3 | C = C，记1 | [A, B, C] |

揭示顺序为 2 → 1 → 3。结束时，按原答案位置整理：

~~~text
标准答案 target              = [A, B, C]
评分预测 scored_predictions  = [A, X, C]
逐位置对错 correct           = [1, 0, 1]
最终输入 state               = [A, B, C]
~~~

单题得分是 \((1+0+1)/3=2/3\)。不能拿最终输入 [A, B, C] 评分，它已经由评价程序回填为标准答案，用它比较会虚假地得到满分。

还要注意：第二轮位置3的候选预测 Z 没有被选中，因此不记错；第三轮基于新的输入重新预测为 C，这时才被选中并正式记分。同样，第一轮位置1的候选 D 也不进入最终评分。

## 6. 对应的完整数学定义

以下位置编号均指答案区域，问题提示 \(p\) 始终保持不变。

### 6.1 初始状态

设第 \(t\) 轮开始前的答案区域为 \(x^{(t-1)}\)，未评价位置集合为 \(R_t\)。初始化为：

$$
x^{(0)}=[\mathrm{MASK},\ldots,\mathrm{MASK}],
\qquad R_1=\{1,\ldots,L\}.
$$

每轮模型的完整输入是 \([p,x^{(t-1)}]\)。

### 6.2 候选预测与置信度

从本轮前向中取得各剩余位置 \(i\in R_t\) 的 logits。记允许的普通 token 集合为 \(V_{\mathrm{allow}}\)，屏蔽后的 logits 为：

$$
\tilde\ell_{t,i}(v)=
\begin{cases}
\ell_{t,i}(v),&v\in V_{\mathrm{allow}},\\
-\infty,&v\notin V_{\mathrm{allow}}.
\end{cases}
$$

为与当前代码的温度约定一致，令 \(\tau=T\)（当 \(T>0\)），否则 \(\tau=1\)。计算：

$$
P_{t,i}(v)=\operatorname{softmax}(\tilde\ell_{t,i}/\tau)_v,
\qquad
\hat y_{t,i}=
\begin{cases}
\arg\max_v\tilde\ell_{t,i}(v),&T=0,\\
\text{从 }P_{t,i}\text{ 中抽样},&T>0.
\end{cases}
$$

候选预测的置信度定义为：

$$
h_{t,i}=P_{t,i}(\hat y_{t,i}).
$$

### 6.3 轮数、每轮数量与选位

默认总轮数 \(K=L\)，每轮评价一个位置。若显式配置正整数步数 \(s\)，则 \(K=\min(s,L)\)。第 \(t\) 轮评价数量为：

$$
c_t=\left\lfloor\frac{L}{K}\right\rfloor
+\mathbf 1[t\le L\bmod K],
\qquad t=1,\ldots,K.
$$

将 \(R_t\) 中的位置按 \((-h_{t,i},i)\) 升序排列，取前 \(c_t\) 个，组成 \(S_t\)。所有位置在全部轮次中恰好选中一次。

### 6.4 保存预测并评分，然后回填

对每个 \(i\in S_t\)，先执行：

$$
\hat y_i^{\mathrm{score}}\leftarrow\hat y_{t,i},
\qquad r_i\leftarrow\mathbf 1[\hat y_{t,i}=y_i].
$$

保存完成后统一更新输入与集合：

$$
x_i^{(t)}=
\begin{cases}
y_i,&i\in S_t,\\
x_i^{(t-1)},&i\notin S_t,
\end{cases}
\qquad R_{t+1}=R_t\setminus S_t.
$$

每轮开始前都满足：已评价位置为标准 token，未评价位置为 mask。结束时 \(R_{K+1}=\varnothing\)，且 \(x^{(K)}=y\)，后一个等式只是回填完成的结果。

### 6.5 单题分数

$$
s_q=\frac{1}{L}\sum_{i=1}^{L}r_i
=\frac{1}{L}\sum_{i=1}^{L}
\mathbf 1[\hat y_i^{\mathrm{score}}=y_i].
$$

分母是标准答案 token 数；比较的是同位置 token ID 是否相同，不是文字相似度或预测概率平均值。

## 7. 伪代码：与当前实现对应的流程

~~~text
输入：模型、问题提示 prompt、标准 token 序列 target、轮数 K、温度 T、种子

state = 全部为 MASK 的答案区域
remaining = 全部答案位置
scored_predictions = 全部为空
correct = 全部为空
trace = 空列表

for t = 1 到 K:
    logits = 模型前向(prompt + state)，只取得 remaining 位置的 logits
    candidates, confidence = 屏蔽特殊 token 后，按温度规则确定候选预测和置信度
    selected = 按置信度降序选取本轮数量，平局按位置升序

    # 第一阶段：本轮输入保持不变，保存预测与评分
    for i in selected:
        scored_predictions[i] = candidates[i]
        correct[i] = int(candidates[i] == target[i])
        trace 保存(轮次, 位置, 候选预测, 置信度, 标准 token, 对错)

    # 第二阶段：全部评分完成后，统一构造下一轮输入
    for i in selected:
        state[i] = target[i]
    remaining = remaining 去掉 selected

确认所有位置恰好评分一次
score = sum(correct) / len(target)
返回 score、scored_predictions、correct、trace
~~~

target 始终只读。回填发生在评价进程的模型输入张量中，不写入数据集 JSON，也不更新模型参数。

## 8. 五个指标如何接在单题分数之后

五类问题沿用现有读取器和任务构造方式，区别在于评价的问题与对应标签：

| 指标 | 题目组 | 使用的标准答案 |
| --- | --- | --- |
| ES | edit | 新事实答案 |
| GS | generalization | 同一新事实答案 |
| LS | preservation | 无关题自己的标准答案 |
| person_score | persona | 角色化问题对应的新事实答案 |
| mhop_score | portability | 多跳题自己的答案 |

每道题都完整执行上述流程，得到 \(s_q\)。LS 也是标准答案 token 正确率，不是 KL 散度或前后预测一致率。存在至少一道可评价题时，缺少的可选题组报告无适用题，而非 0 分；若所选题组全部无题，当前入口直接报错，不生成全空评价报告。

### 编辑前后分别评价

同一道题在原模型和对应的编辑后模型上分别执行完整流程，得到 \(s_q^{\mathrm{before}}\) 与 \(s_q^{\mathrm{after}}\)。两次均从全 mask 状态开始，不复用另一侧的回填状态。

| 编辑模式与情况 | after 使用的权重 |
| --- | --- |
| independent，案例被接受 | 该案例保存的编辑后权重 |
| independent，案例被拒绝 | 原始权重；复用 before 的预测及轨迹 |
| sequential，任一已尝试事实 | 连续编辑结束后的最终权重 |

两侧问题、标准答案、分词、轮数规则、温度与种子设置保持一致，但各自根据当前模型的置信度选择位置。

### 汇总与平均

在某指标组、某统计子集中，设有 \(N\) 道题，来自 \(C\) 个有题的源案例；案例 \(c\) 的题目集合为 \(Q_c\)，题数为 \(n_c\)。沿用两种平均方式：

$$
\operatorname{probe\_macro}^{u}
=\frac{1}{N}\sum_{q=1}^{N}s_q^u,
\qquad
\operatorname{case\_macro}^{u}
=\frac{1}{C}\sum_{c=1}^{C}
\left(\frac{1}{n_c}\sum_{q\in Q_c}s_q^u\right),
\qquad u\in\{\mathrm{before},\mathrm{after}\}.
$$

分别计算对应的 \(\Delta=\mathrm{after}-\mathrm{before}\)。继续区分 all、accepted、rejected，记录题数、覆盖状态；空组不代入上述分母。

probe_macro 与原版 UltraEdit 一样先算单题比例、再对题目等权平均。case_macro 先对案例内部求平均，再对案例等权平均，题数不等时两者可能不同。平均方式相同不代表评价条件相同。

## 9. 阅读结果时，记住这些边界

### 9.1 沿用置信度选位规则，具体顺序会重新计算

本方案保留的是“按当前候选预测置信度选位”的规则。回填标准 token 后，下一轮输入可能不同于自主去噪，因此 logits、置信度与具体揭示顺序都可能变化。不能把它理解成固定重放原自主去噪轨迹的位置顺序。

编辑前后也可能走不同顺序。分数差值既包含模型参数变化的影响，也可能包含正确 token 提供顺序变化的影响。若另行设计固定共同顺序实验，应使用独立设置标记，不能与本方案混为一谈。

### 9.2 与 UltraEdit 对齐的是正确上下文思想

原版 UltraEdit 在因果注意力下使用左侧正确答案前缀；本方案已经回填的正确 token 可以在当前位置左侧或右侧。它评价的是正确部分答案条件下的 mask 补全能力，不能称为严格的 UltraEdit 自回归前缀评价。

标准答案自身的位置在评分前始终是 mask，但已评价的其他位置可以提供答案线索。这是本协议定义的条件，不能据此直接推断自由生成整段答案的成功率。

### 9.3 轮数与温度属于评价条件

\(K=L\) 时逐个评价并回填；\(K=1\) 时全部位置在全 mask 状态下同时预测，回填发生在所有评分之后，对该题分数没有作用。其他配置相同时，\(K=1\) 的评分应与现有自主去噪单轮结果一致。

因此，比较实验应保持相同轮数规则与温度，记录每题实际轮数和每轮选位数量；不能将不同设置的分数直接混合。

### 9.4 评分预测序列不是一段自主生成答案

\(\hat y^{\mathrm{score}}\) 是各位置在不同轮次被选中时的预测记录，按答案位置拼接而成。如果报告完全匹配率，它表示“每个位置在各自评分时均预测正确”；前后预测一致率也只比较两侧保存的评分预测。两者均不能使用最终回填状态计算。

长答案场景中，已回填内容还可能直接提示后续内容。因此，本协议可用于研究条件预测变化；研究短答案编辑是否影响实际长答案生成时，还需要配套的生成评价。

## 10. 当前实现位置与核查要点

回填协议以 diffusion_gold_v1 标识，自主去噪协议以 diffusion_short_v1 标识；二者共用 mdlm_ultraedit.json。将 `protocol` 设为所需协议即可切换，temperature 默认 0，steps 默认 null（即 \(K=L\)）。命令：python -u evaluate.py --run-dir runs/<run_id> --config configs/evaluation/mdlm_ultraedit.json。

GenerationRequest 仍不携带标准答案。runner 仅为新协议向 generate 独立传入 target；generate 内部区分 state、scored_predictions 和 correct。Prediction.token_ids/text 保存评分预测，correct 保存逐位置对错，trace 保存逐轮选位及评分。最终回填 state 不返回用于评分。

manifest.json 记录协议、温度、种子及结果含义；predictions.jsonl 保存题目标识、before/paired 阶段、初始请求及两侧 Prediction。trace 每轮记录 step、positions、predicted_ids、confidence、target_ids、correct，其中 positions 是从 0 开始的答案区域下标。trace 长度是实际轮数，各轮 positions 长度是选位数量，结合初始请求可以重建回填输入。

实现与测试需保持以下性质：

- 每个答案位置恰好评价一次；未选中位置继续保持 mask。
- 评分发生在回填之前；同轮所有评分使用同一次前向结果。
- 错误预测在评分记录中保留，下一轮输入使用对应的正确 token。
- 最终分数来自评分记录；最终输入即使等于标准答案也不参与评分。
- 回填仅发生在独立评价输入中，不修改数据集 JSON、编辑产物或 MDLM 的状态采样、优化、合并及接受逻辑。
