# 原版 UltraEdit 各评价指标的完整计算逻辑

本文以本仓库历史提交 8ec6479 中的 UltraEdit 原版代码为准。ES、GS、LS、person_score、mhop_score 都使用**同一个单题公式**：标准答案中预测正确的 token 比例。它们使用不同的问题和标准答案，最后分别按题目求平均。

## 快速认识五项指标

| 指标 | 问题 | 标准答案 | 观察重点 |
| --- | --- | --- | --- |
| ES | 原始编辑问题 | 新事实答案 | 原问法是否答对 |
| GS | 同一事实的改写问题 | 新事实答案 | 改写问法是否答对 |
| LS | 与编辑无关的问题 | 无关题原有的标准答案 | 无关知识是否仍答对 |
| person_score | WikiBigEdit 的角色化问题 | 新事实答案 | 角色化问法是否答对 |
| mhop_score | WikiBigEdit 的多跳问题 | 多跳题单独给出的答案 | 多跳问题是否答对 |

这五项都不是“整句完全正确率”。一道题答案有四个 token，预测对三个，单题分数就是 0.75。

## 第一步：确定实际进入评估的验证记录

原版数据基类读取验证集 JSON，默认截取前 dataset.n_edits × num_seq 条。验证 DataLoader 每次取 dataset.n_edits 条，设置 drop_last=True；sequential_valid() 最多处理 num_seq 个完整批次。因此，最终分母只涉及**实际进入这些批次的题目**，不一定涵盖整个验证文件。

四个数据集读取器分别把每条记录转换为题目组：

| 数据集 | 编辑题 → 标准答案 | 改写题 → 标准答案 | 无关题 → 标准答案 | 额外题 |
| --- | --- | --- | --- | --- |
| ZSRE | src → ans | rephrase → ans | loc 加问号 → loc_ans | 无 |
| UltraEditBench | prompt → ans | rephrase_prompt → ans | loc → loc_ans | 无 |
| WikiBigEdit | update → ans | rephrase → ans | loc → loc_ans | personas → ans；mhop → mhop_ans |
| FEVER | prompt → alt | 从 equiv_prompt 随机选一条 → alt | unrel_prompt → unrel_ans | 无 |

箭头左边是问题文本，右边是标准答案文本。FEVER 用 random.choice 选改写题，不同运行可能选中不同题目。只有 WikiBigEdit 报告 person_score；mhop_score 还要求 eval_mhop=True。

## 第二步：构造自回归模型的输入与标签

设提示分词为 $p_1,\ldots,p_P$。读取器先给答案文本加一个**前导空格**，再分词为 $y_1,\ldots,y_L$。各读取器构造的序列相同：

| 序列 | 内容 | 长度 |
| --- | --- | --- |
| 模型输入 input_ids | $[p_1,\ldots,p_P,y_1,\ldots,y_{L-1}]$ | $P+L-1$ |
| 对齐标签 labels | $[\underbrace{-100,\ldots,-100}_{P-1},y_1,\ldots,y_L]$ | $P+L-1$ |

−100 表示不参与评分；批处理的填充标签也用 −100。最后一个提示 token 位置预测 $y_1$；输入中的 $y_1$ 位置预测 $y_2$；依此类推。预测后续答案 token 时，模型看到的是前面**正确的答案 token**，这属于正确答案前缀条件下的预测（teacher forcing）。

例如提示为 $[p_1,p_2]$，答案为 $[A,B,C]$：

| logits 所在位置 | 已看见的正确答案 token | 此位置的标签 |
| --- | --- | --- |
| $p_1$ | 无 | −100，不计分 |
| $p_2$ | 无 | $A$ |
| $A$ | $A$ | $B$ |
| $B$ | $A,B$ | $C$ |

即使模型在第一个位置预测错了 $A$，评估第二个答案 token 时输入的仍是**正确的 $A$**。因此，这不是从问题出发自由生成整段答案的成功率。

### 为什么预测错误不会传到后续位置

原版一次构造所有位置的输入和标签，只做一次自回归模型前向。因果注意力使第 $j$ 个答案位置只能看到问题和左侧的**标准答案** $y_1,\ldots,y_{j-1}$。各位置的预测值只用于事后评分，不写回输入。因此，前一位置即使预测错误，后一位置看到的仍是正确 token。

这表示各位置分别判对错，但并非互不相关：后续位置依赖正确的前文。这样测量的是“在之前答案正确的条件下，当前 token 能否预测正确”，排除了早期生成错误的连锁影响。原版并不是先预测、再逐轮改正答案；正确前缀从一开始就在输入中。

## 第三步：逐题计算正确 token 比例

模型前向传播后，第 $j$ 个答案预测位置对每个词表 token $v$ 都有 logit $z_j(v)$。取该位置最大 logit 对应的 token：

$$
\hat y_j=\operatorname*{argmax}_{v}z_j(v).
$$

一道题 $q$ 的分数为：

$$
s_q=\frac{1}{L_q}\sum_{j=1}^{L_q}\mathbf{1}[\hat y_{q,j}=y_{q,j}].
$$

$L_q$ 是有效答案 token 数，指示函数在预测正确时为 1。代码中的 succ_ratios(logits, labels) 先算 logits.argmax(-1) 与 labels 相等的数量，再除以 labels != −100 的数量。提示与填充位置不进入分母。

例如标准答案 $[A,B,C,D]$，模型各位置最大 logit 对应 $[A,X,C,D]$，命中值是 $[1,0,1,1]$，得 $3/4=0.75$。比较的是 token ID 是否相等，不是概率均值，也不是解码后文字是否相似。succ_ratios() 另有 old_labels 比较分支，但最终五项指标调用时未传 old_labels。

## 第四步：同一指标组内逐题求平均

令 $Q_g$ 为问题组 $g$ 中实际评估的题目集合，$N_g=|Q_g|$。sequential_valid() 把该组每道题的 $s_q$ 放进同一个列表，再使用 numpy.mean：

$$
M_g=\frac{1}{N_g}\sum_{q\in Q_g}s_q.
$$

五个组与最终名称对应如下：

$$
\mathrm{ES}=M_{\mathrm{edit}},\quad
\mathrm{GS}=M_{\mathrm{equiv}},\quad
\mathrm{LS}=M_{\mathrm{unrel}},\quad
\mathrm{person\_score}=M_{\mathrm{person}},\quad
\mathrm{mhop\_score}=M_{\mathrm{mhop}}.
$$

这是**先按一道题的答案长度计算比例，再对题目等权平均**。例如，两道编辑题的答案长度分别为 2 和 4，单题得分为 0.5 和 1，则 ES 为 $(0.5+1)/2=0.75$；不是把全部六个 token 混合后计算得到的 $5/6$。也没有先按源案例求平均。组内没有题目时，原版 numpy.mean 对空列表会得到 NaN 并伴随警告；NaN 不表示 0 分。

## 五项指标的完整计算例子

假设最后模型评估两条 WikiBigEdit 记录，每条记录在每个启用的组中各有一道题。逐题结果如下；分数中的分子是预测正确的 token 数，分母是该题答案 token 数：

| 记录 | 编辑题 | 改写题 | 无关题 | 角色化题 | 多跳题 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 第 1 条 | $1/2=0.5$ | $2/2=1$ | $3/4=0.75$ | $2/2=1$ | $0/2=0$ |
| 第 2 条 | $2/2=1$ | $0/2=0$ | $1/4=0.25$ | $1/2=0.5$ | $1/2=0.5$ |
| 对应指标均值 | **ES = 0.75** | **GS = 0.5** | **LS = 0.5** | **person_score = 0.75** | **mhop_score = 0.25** |

例如 ES 的计算是 $(0.5+1)/2=0.75$，LS 的计算是 $(0.75+0.25)/2=0.5$。若未启用多跳评估，就不会报告最后一列。

## 最终模型状态与 LS 的准确含义

原版 sequential_valid() 先按批次依次应用编辑增量，收集题组；**全部编辑完成后**，用最后的模型回测所有题目。故上述每个 $s_q$ 都来自这一次连续编辑后的最终模型，不是每条记录编辑完立即得到的分数。

训练时记录的 gen_loss 是改写题交叉熵损失，loc_loss 是无关题上编辑前后输出分布的 KL 损失，用于学习或约束编辑。最终报告中的 **LS 则是无关题原有标准答案的正确 token 比例**，仍使用上面的 $s_q$ 与 $M_g$；它不是 KL 散度，也不是编辑前后输出相同的比例。原版最终五项指标也不包含编辑前分数、前后差值或整句完全匹配率。
