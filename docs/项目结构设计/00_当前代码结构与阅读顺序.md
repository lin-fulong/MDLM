# 当前代码结构与阅读顺序

更新：2026-10-29。本文对应当前 `main` 分支的内存运行流程。数学定义仍以[《最终逻辑 V1.0》](../最终逻辑%20V1.0.md)为准；旧版分阶段开发记录保留在其他文档中，所列阶段命令与产物目录不再是当前运行方式。

## 运行方式

```bash
conda activate mdlm
python -u main.py --editor mdlm --config configs/full_run.json
```

`main.py` 解析参数，按 `--editor` 选择并按需导入算法。MDLM 的实际流程在 `MDLM/runner.py`：读取案例和配置、准备保持输入、加载一次模型，然后按源案例执行编辑。`--case-id` 可选一个或多个源案例/事实；默认各源案例独立编辑，`--sequential` 只把已接受的权重留给下一案例。保持输入始终由完整数据集确定，案例筛选只决定编辑对象，不改变确定性划分。

同一源案例下的所选事实联合编辑，案例与事实顺序沿用数据集；按事实编号筛选时只编辑该事实。连续模式在某案例被拒绝后，保留上一接受模型并继续处理后续案例。此循环是跨案例实验方式，与《最终逻辑 V1.0》11.1 中“同一事实集最多刷新一次”的外轮不同；当前入口不执行该刷新，也不执行独立生成评价。

每轮在内存中依次执行：

```text
审核后的案例 → P1 去噪轨迹与监督 → P2 参考键 K、保持统计 C
             → P3 固定写回因子 Q → P4 优化残差 R
             → P5 合并、开发集门槛、接受或精确回退
```

P0 的数据、模型和适配器边界直接体现在现行读取、对齐与模型接口中；仓库不再保留独立的数据校验和 P0 冒烟脚本。

## 现行文件职责

| 位置 | 职责 |
| --- | --- |
| `main.py` | 统一命令行入口和 `--editor` 算法注册表。 |
| `MDLM/runner.py` | 四个函数负责项目路径、输出目录名、案例筛选、实验运行；加载一次模型，固定最初 θ₀/W₀，控制独立/连续编辑与本轮恢复。 |
| `MDLM/states.py` | 去噪轨迹筛选、兼容状态、事实/状态/位置三级监督权重。 |
| `MDLM/keep_statistics.py` | 公式（5）的未中心化加权二阶矩 $C$ 累计，不生成诊断报告。 |
| `MDLM/writeback.py` | `WritebackConfig`、公式（6）～（9）的固定 $Q$ 求解；另保留其他模块共用的 Frobenius 范数计算。 |
| `MDLM/candidate.py`、`MDLM/optimize.py` | 全位置 $R(Qk)$ 分支、固定 Q 的多层 R 联合优化、预定检查点中的最佳候选；仅保留目标值轨迹和最佳步数。 |
| `MDLM/merge.py`、`MDLM/acceptance.py` | 固定 ΔW=RQ、从 W_b 重建公共 α 试步、因子/实际合并前向一致性、三个独立开发门槛与精确回退。 |
| `MDLM/workflow.py` | 四个函数：最初 θ₀ 的完整词表保持参考、单轮监督 → K/C → Q → R → 接受、最终目标权重保存和重载。 |
| `model/base.py` | 六种输入/结果数据结构、八个适配器接口，以及保持原精度的张量摘要；声明算法所需数据，不直接计算损失或更新。 |
| `model/registry.py` | 选择模型适配器。 |
| `model/adapters/llada_8b_instruct.py` | LLaDA 本地加载、短答案对齐、单条/等长批量实际 FFN 输入捕获、可微 logits、自主去噪与 W_b 快照/恢复；捕获与可微读出共用模型调用。 |
| `data/readers/reviewed_cases.py` | 三个函数映射题目字段、逐请求展开 gold_ready 源案例、可选写出转换文件；同源事实保留共同来源，共享保持题仅附到首个事实。 |
| `data/readers/json_cases.py` | 两个函数：统一读取 JSON/JSONL 为列表，按首条记录分派源格式转换；用途标签辅助函数目前没有正式调用方。 |
| `data/validation/alignment.py` | 按 tokenizer 字符偏移定位唯一主体及末 token，保持提示分词前缀不变，返回单独的短答案 token；供编辑/开发适配器构造全 mask 输入。 |
| `util/prepare_dataset_inputs.py` | 两个函数构造保持题全 mask 上下文，按题目摘要去重、固定划分并分配题/位置权重；返回统计、训练、开发保持和 edit 开发探针。 |
| `util/collect_denoise_states.py`、`util/extract_reference_keys.py` | 采集去噪轨迹、从初始全 mask 状态提取 $K$ 并重放核对。 |
| `util/extract_keep_statistics.py` | 每批保持输入只前向一次，逐层返回模块名和 $C$；用于求出该层 $Q$ 后即可释放。 |
| `util/gpu_runtime.py` | 选择 CPU/CUDA 设备；resident 模式关闭 TF32，退出时恢复原 TF32 设置。 |
| `util/io.py` | 读取配置、保存运行摘要/模型元数据，并生成保持输入确定性划分所用的 SHA-256 排序键。 |
| `configs/full_run.template.json`、`configs/full_run.json` | 当前全流程参数模板和默认配置；其中 `p1`～`p5` 控制对应算法步骤。 |

`MDLM/contracts.py`、旧的逐阶段磁盘入口、独立数据校验和 P0 冒烟脚本已经删除。数值参数类位于对应算法模块。`configs/*_example_only.json` 是旧逐阶段技术联调留下的示例，不作为 `main.py` 的全流程配置。`tests/` 只在本地保留，由 `.gitignore` 排除。

保持统计的运行时诊断、重复前向和独立重放已移除，原辅助文件 `util/validate_matrix_artifacts.py` 已删除。`p2_keep` 只接受 `accumulation_dtype`、`storage_dtype`、`device`、`batch_keep`，默认配置中的空字典继续适用。公式（5）的数学对照和修改前后数值回归放在本地测试中。

写回求解直接返回 CPU 上的固定 Q，不再返回诊断报告。`p3` 只接受 `ridge_by_layer`、`compute_dtype`、`storage_dtype`、`device`，默认配置继续适用；旧的检查容差、分块诊断和失败策略参数已移除。写回公式与修改前后数值对照在本地测试中验证。

`p4` 保留 `rho_by_layer`、`beta`、`learning_rate`、`max_steps`、`checkpoints`、`microbatch_size`、`residual_dtype`、`seed` 八项参数。优化器仍为原有 Adam，返回最佳 R、目标值轨迹和最佳步数，不再导出优化器状态或资源诊断。R 从零开始，Q 与基准权重固定，跨层梯度和原有候选选择规则保持；推理缓存转为可反传张量的功能继续保留。

`p5` 保留 `alphas`、`delta`、`tau_g`、`tau_u`、`epsilon`、`compute_dtype`、`equivalence_atol`、`equivalence_rtol`、`chunk_size` 九项参数，默认值和原试步顺序不变。开发编辑仍使用全 mask 短答案输入，按事实、同事实探针和 token 均分；协议直接体现在 `development_edits` 中，旧 `edit_protocol` 标记已移除。开发保持始终执行完整词表 KL(theta_0 || theta_alpha)，U 从实际存储权重计算相对最初 W_0 的累计净变化。

P5 已移除参数版本/摘要/别名扫描、辅助 V* 与公式（14）的运行时诊断、配置检查和附带阶段报告的异常包装。每次实际写回仍只覆盖选定目标权重，拒绝或运行异常时恢复 W_b；非有限试步、同 α 前向不一致、三个开发门槛不通过的选择行为保留。正常接受/拒绝的逐试步结果结构不变，运行异常恢复后直接上抛，由 runner 记录运行失败。

`workflow.reference_examples` 由 runner 在首次编辑前调用，训练和开发保持输入分别计算最初 θ₀ 的完整词表 log 概率。`edit_round` 消费已采集轨迹，不重新采样；逐层计算 C 并立即求 Q，退出候选上下文后才实际合并，未选出 R 时直接结束本轮。数据划分、轨迹采样、W₀ 缓存和独立/连续编辑控制均由 runner 负责。

runner 已合并重复的设备选择分支，并移除层编号、输入模式、example-only 标签、事实 ID 唯一性、整模型 GPU 驻留扫描及加载后重复目标层检查。它按既定数据与配置格式执行；不再由入口阻止这些非法或示例输入，不能把示例运行当作正式算法效果。模型适配器、输入准备和采样自身的检查不变。目录名边界、指定案例不存在时的报错、异常恢复和运行摘要保留；默认配置、设备优先级、resident 精度设置、C/Q 计算设备及保持分批规则均不变。

`model/base.py` 中 `MaskedEditInput` 与 `EditTarget` 分别保存模型输入和监督答案；`DenoiseTrace` 在内存中保存前向前状态、原始 logits 摘要、揭示记录和终态。`ForwardCapture` 的激活是实际目标 FFN 输入：编辑取键为向量，保持统计捕获为位置矩阵。`TargetWeightSnapshot` 用于恢复本轮 W_b，runner 的 originals 则是公式（17）的固定 W₀。数据字段、顺序、frozen、状态相等与哈希规则均保持；张量摘要按原 header 和原始字节分段计算同一个 SHA-256，避免拼接时再复制整个字节串。

共享接口目前支持现行 LLaDA 的单序列、隐式连续位置流程，没有显式时间或分块字段。四个方法是原有抽象方法，另外四个默认抛出 NotImplementedError；完整 MDLM 适配仍需实际实现相应能力。模型加载、目标模块命名和检查也仍由具体适配器提供。本次补充接口说明，没有扩充模型适配范围。

LLaDA 适配器的单条编辑、单条保持与等长批量保持共用 `_forward_capture`，使用 pre-hook 复制 `ff_out` 实际输入，并在 finally 中移除 hook。`_forward` 统一构造 token/attention 张量、关闭 KV cache 并读取原位置的完整词表 logits；捕获调用它时使用 no_grad，可微读出由调用方控制梯度。单条激活字典沿用实际调用顺序，批量沿用配置层序，输入与位置顺序不变。现有输入/模块/快照检查继续保留；批量捕获失败使用共用的具体错误提示。

`sample_denoise` 保留原受控窗口策略：目标仅用于构造窗口长度及随后监督，采样不接收目标 token；原始 logits 先计算摘要，再在 float32 副本中屏蔽特殊 token，按温度选择普通 token，以预测置信度排序并逐步揭示。前向前状态进入内存轨迹，终态单列，不重新掩码。该采样配方服务公式（1），没有独立公式编号；它不是公式（2）的完整词表监督分布。本次没有修改采样策略，也未执行完整 8B 实验。

`prepare_inputs` 接收完整数据集，按 `strip(prompt)` 的摘要去重并保留首次原始题目/答案，再按 seed 和题目摘要的联合摘要排序。原比例计数决定互斥的 `dev`、`test`、`statistics_train`；`test` 仅保留题目摘要，不编码或执行评价。编码先训练后开发：C 捕获模板化提示末 token 与答案 mask，位置权重为 scale/(训练题数×该题捕获位置数)；训练/开发 KL 仅读答案 mask，权重为 1/(各组题数×该题 mask 数)。保持答案仅确定稳定窗口，不作为 KL 标签；最初 θ₀ 分布由 runner/reference_examples 提供。统计与训练复用同一训练输入，开发保持使用独立分区。

当前 `dev_edit_policy=edit_probe` 直接返回各案例的 edit 探针，开发编辑会复用训练所用的题目；保持分区隔离不能解释为编辑开发题也已独立留出。摘要划分只保证当前题目键互斥，不负责语义、来源或 tokenizer 归一化后的跨用途隔离。题目来源、全 mask 窗口、捕获位置、均分权重和分区比例是当前具体配方，数学文档没有唯一指定这些选择。本次仅整理两个函数的重复构造与命名，原划分/权重/编码顺序和错误检查均保留。

`align_edit_prompt` 接收已套聊天模板的提示。按与主体字符区间相交的非空 offset 定位 token，允许字节 token 共享字符偏移和边缘空格合并，仍要求覆盖完整、下标连续及左边界有序；主体须在模板化提示中唯一出现。提示和“提示+答案”各分词一次，只有前缀相同才能截取监督答案；禁止答案特殊 token，并要求关闭清理后的 decode 与原答案逐字相同。适配器随后从提示 token 数起构造等长全 mask 窗口，答案单独进入 EditTarget，主体最后位置供公式（4）取键。本文件为公式（1）～（3）和开发编辑准备目标及位置，不计算状态筛选或损失；保持输入仍由 encode_keep 单独构造。

`adapt_reviewed_cases` 保留源案例与请求顺序，将 edit_requests 与 edit_questions 按下标配对。单请求沿用源 case_id，多请求使用 request_id，同时保留 source_case_id/source_request_id；runner 据共同来源分组联合编辑。fact_core.new_object 来自 experimental_new_answer，实际监督来自编辑题 expected_new_answer；当前转换不核对二者一致性或题目关系，依赖源数据审核。gold_ready 沿用原真值判断，review_status 仅复制。独立测试题不进入输出，free_form_qa/portability 保持为空；旧版阅读清单中的评价题转换/生成视图描述不适用于当前链路。保持题仅挂在首个事实，prepare_inputs 仍读取完整转换集，因此按事实筛选不会丢失该源案例的保持题。

`load_cases` 从 runner 传入的 dataset 路径读取 UTF-8 文件：精确的 .jsonl 后缀逐非空行解析，其他后缀沿用整文件 JSON 解析。数组直接保留，单对象包装成列表；只有首条同时含 edit_requests/edit_questions 才调用审核源格式转换，未逐条猜测混合格式。普通运行格式原样返回，不按 split 或 example_only 自动筛除。case_purpose 的判定优先级是 example_only → test → gold/pilot/dev → edit，删除 P0 冒烟脚本后暂时没有正式调用方；开发保持划分由 prepare_inputs 完成。本文件提供后续公式（1）～（4）所用事实及顺序，不计算编号公式；旧版“提取无答案评价输入”的描述已不适用。

`execution_context` 包围 runner 的完整算法运行。配置为 resident 时关闭矩阵乘法和 cuDNN 的 TF32，结束或异常退出后恢复进入前的两个开关；显式 CUDA 设备会被设为当前设备。它不负责移动模型、不创建推理/反传上下文，也不恢复进入前的当前 CUDA 设备。`backend=subprocess` 仅保留旧精度语义，当前仍是单进程运行。该工具不直接实现公式（1）～（18），只是固定共同的设备和浮点环境。

`util/io.py` 不是数据集读取器：`read_json` 读取 runner 配置及最终模型元数据，`write_json` 保存运行摘要及模型元数据；数据集仍由 `data/readers/json_cases.py` 负责。`config_digest` 对紧凑、键排序的 UTF-8 JSON 计算 SHA-256，供 prepare_inputs 去重和按 seed 稳定排序，因此间接固定公式（5）（10）（16）的保持输入集合，但摘要计算本身没有算法公式编号。

## 输出与重载

已建立的运行目录 `runs/<run_id>/` 会写入 `run_report.json`。独立模式仅为被接受的案例创建 `case_<index>/`；连续模式在全部轮次结束后创建一个 `final_model/`。每个最终模型目录只有 `model.json` 和 `target_weights.safetensors`，保存目标层的最终权重；重新加载时还需要 `model.json` 所记录的原始模型路径。

```python
from MDLM.workflow import load_final_model

adapter, model = load_final_model("runs/<run_id>/final_model", device_map="cuda:0")
```

运行时不会保存各阶段的轨迹、$K/C/Q/R$、优化器状态或阶段清单。旧 `runs/` 中的这些文件若仍存在，属于历史运行结果。`--cache-dir`、`--no-cache` 已移除，评估代码也不在当前算法运行链路中。数据集与原始模型目录都由配置或命令行指定，仓库不上传其大文件。

最终权重直接按原精度保存和覆盖，workflow 已移除保存后立即读回、加载时额外的目标层检查/整层快照/回滚，以及保持参考和阶段连接的重复检查。文件名、metadata、函数签名及正常返回结果不变；最终结果仍依赖原始模型目录，保存的是最终目标权重，不是待重复相加的增量。

## 建议逐文件阅读

1. `README.md` → `main.py` → `configs/full_run.template.json` → `MDLM/runner.py`：先看启动参数、选例、模型加载和轮次边界。
2. `data/readers/reviewed_cases.py` → `data/readers/json_cases.py` → `data/validation/alignment.py` → `model/base.py` → `model/registry.py` → `model/adapters/llada_8b_instruct.py`：确认案例、token 与模型接口。
3. `util/prepare_dataset_inputs.py` → `util/collect_denoise_states.py` → `MDLM/states.py`：理解输入划分、无答案采样和监督权重。
4. `util/extract_reference_keys.py` → `MDLM/keep_statistics.py` → `util/extract_keep_statistics.py`：理解 $K/C$ 的捕获位置、显式权重、累计精度和逐层计算。
5. `MDLM/writeback.py` → `MDLM/candidate.py` → `MDLM/optimize.py`：核对固定 $Q$、临时分支与 $R$ 优化。
6. `MDLM/merge.py` → `MDLM/acceptance.py` → `MDLM/workflow.py`：核对公共步长、开发门槛、回退和最终结果重载。
7. `util/gpu_runtime.py` → `util/io.py` → 回看 `MDLM/runner.py`：检查执行精度、结果目录和异常处理。

算法定义和代码实现要区分：历史阶段文档记录了旧版开发与技术联调证据，不能据此推断当前版本已经完成正式 8B、多事实、多层实验。
