# 当前代码结构与阅读顺序

更新：2026-10-29。本文对应当前 `main` 分支的内存运行流程。数学定义仍以[《最终逻辑 V1.0》](../最终逻辑%20V1.0.md)为准；旧版分阶段开发记录保留在其他文档中，所列阶段命令与产物目录不再是当前运行方式。

## 运行方式

```bash
conda activate mdlm
python -u main.py --config configs/main.json
```

`main.py` 解析参数，按主配置的 `editor` 或命令行 `--editor` 选择并按需导入算法。MDLM 的实际流程在 `MDLM/runner.py`：组合配置、按适配器层序对应 λ/ρ、读取案例、准备保持输入、加载一次模型，然后按源案例执行编辑。主配置的 `mode` 选择独立/连续编辑，`case_ids` 筛选案例/事实，`max_cases` 按源案例限量；对应命令行覆盖配置。保持输入由完整已读取案例集或显式 keep_path 确定，case_ids/max_cases 只决定编辑对象，不改变确定性划分；source_limit 则限定读取范围。

同一源案例下的所选事实联合编辑，案例与事实顺序沿用数据集；按事实编号筛选时只编辑该事实。连续模式在某案例被拒绝后，保留上一接受模型并继续处理后续案例。此循环是跨案例实验方式，与《最终逻辑 V1.0》11.1 中“同一事实集最多刷新一次”的外轮不同；编辑入口不执行该刷新。编辑完成后可由 `evaluate.py` 独立评价最终产物。

每轮在内存中依次执行：

```text
data/dataset.py → data/readers/：按配置读取案例、转换源格式及可选保持池
  → MDLM/states.py：准备编辑/保持输入、自主去噪、兼容筛选、固定监督
  → MDLM/writeback.py：提取 K、逐层累计 C 并求 Q
  → MDLM/optimize.py：临时分支、损失与残差 R 优化
  → MDLM/merge.py：合并、开发门槛、接受或精确回退
由 MDLM/runner.py 串联单轮计算、案例循环与最终结果存取。
```

P0 的数据、模型和适配器边界直接体现在现行读取、对齐与模型接口中；仓库不再保留独立的数据校验和 P0 冒烟脚本。

## 现行文件职责

| 位置 | 职责 |
| --- | --- |
| `main.py` | 统一命令行入口和 `--editor` 算法注册表。 |
| `MDLM/runner.py` | 配置与案例选择、模型加载、最初 θ₀/W₀ 参照、单轮算法串联、独立/连续编辑，以及最终权重保存和重载。 |
| `MDLM/states.py` | 编辑/开发/保持输入构造、保持题划分与权重、去噪采样/轨迹、兼容筛选和固定监督；实现公式（1）～（3），准备公式（4）（5）（10）（16）的输入。 |
| `MDLM/writeback.py` | 参考键 K、未中心化加权二阶矩 C、固定 Q 求解及共享 Frobenius 范数，公式（4）～（9）；保持逐层累计并释放 C。 |
| `MDLM/optimize.py` | 全位置 $R(Qk)$ 分支、冻结基准、固定 Q 的多层 R 联合优化与最佳候选选择，公式（10）～（12）。 |
| `MDLM/merge.py` | 固定 ΔW=RQ、从 W_b 重建公共 α 试步、因子/实际合并前向一致性、三个开发门槛与精确回退，公式（13）～（18）。 |
| `model/base.py` | `MaskedEditInput`、`KeepModelInput`、`ForwardCapture` 三种共用结构与模型操作接口；不声明 MDLM 监督或采样策略。 |
| `model/registry.py` | runner 和最终模型重载共用的适配器工厂；按需加载本地 tokenizer，默认沿用 LLaDA。 |
| `model/adapters/llada_8b_instruct.py` | LLaDA 本地加载、聊天模板、目标层名/维度、指定层与位置的单条/等长批量捕获、可微 logits，以及通用快照工具的调用。 |
| `data/dataset.py` | 统一读取入口 load_dataset、读取器注册表及 DatasetBundle；兼容原 load_cases、gold_ready 展开和转换命令，不依赖 MDLM。 |
| `data/readers/` | base.py 提供流式记录和文本探针；四个读取器直接按源字段映射，不分词或运行评价，缺字段和解析错误使用原生异常。 |
| `evaluate.py` | 已完成编辑运行的独立评价命令行入口。 |
| `evaluation/` | 编辑产物读取、UltraEdit 问题组、扩散短答案推理、指标汇总及评价报告。 |
| `data/validation/alignment.py` | 按 tokenizer 字符偏移定位唯一主体及末 token，保持提示分词前缀不变，返回单独的短答案 token；供 states 构造全 mask 输入。 |
| `util/nethook.py` | 通用输入/输出捕获、hook 安装/移除、权重快照/恢复、推理缓存转换与原精度张量摘要；不决定捕获位置或算法策略。 |
| `util/gpu_runtime.py` | 选择 CPU/CUDA 设备；resident 模式关闭 TF32，退出时恢复原 TF32 设置。 |
| `util/io.py` | 组合配置、读写 JSON、解析项目相对路径、选择运行目录名，以及通用 JSON 摘要。 |
| `configs/main.json` | 选择算法、模型与数据配置，指定统一种子、编辑模式/选例/源案例数量和输出位置；参数解释见[配置参数说明](../配置参数说明.md)。 |
| `configs/models/llada_8b_instruct.json` | 模型路径、编辑层和运行设备；模块名由适配器确定。 |
| `configs/datasets/cases.json` | 平铺的 dataset_path、keep_dev_fraction、keep_test_fraction 和 statistics_scale。 |
| `configs/editors/mdlm.json` | 平铺的算法超参数，按实际含义命名；λ/ρ 使用标量或按目标层顺序的列表。 |

`MDLM/contracts.py`、旧的逐阶段磁盘入口、独立数据校验、P0 冒烟脚本和本地测试目录已经删除。数值参数类位于对应算法模块。旧配置模板及阶段示例已删除，原 `full_run.json` 已拆成上述四份职责明确的配置。

MDLM 核心仍为 runner、states、writeback、optimize、merge 五个文件；数据读取、模型适配、通用工具和独立评价分别位于各自目录。

依赖方向为 `main → MDLM.runner`、`MDLM → model/data/util`、`model → util`；data 和 util 均不依赖 MDLM，util 不依赖具体适配器。输入策略不再从 model 或 data 反向调用 MDLM，也没有保留旧接口转发层。

`states.py` 内按“输入/轨迹类型 → 记录转换 → 编辑/保持输入与划分 → 采样与轨迹采集 → 兼容筛选与监督”排列。`EditTarget` 和 `DenoiseTrace` 随算法策略归入 states；权重快照类型随通用操作归入 nethook。模型基础层保留共用输入及前向结果。

原辅助文件 `util/validate_matrix_artifacts.py` 已删除；当前内存流程保留关键数值校验，并恢复 P0/轨迹重放和 K 一致性核对。runner/edit_round 的 `keep_options` 传给 writeback/keep_matrices，支持 `accumulation_dtype`、`storage_dtype`、`device`、`batch_keep`；当前 JSON 沿用默认精度，设备和分批由 runner 按 execution 统一决定。公式（5）的数学对照和修改前后数值回归结论保留在历史开发记录中。

写回求解直接返回 CPU 上的固定 Q，不再返回诊断报告。算法 JSON 使用 `ridge`，runner 将其对应到实际模块；内部 `WritebackConfig` 仍接受 `ridge_by_layer`、`compute_dtype`、`storage_dtype`、`device`。旧的检查容差、分块诊断和失败策略参数已移除，默认精度不变。写回公式与修改前后数值对照结论保留在历史开发记录中。

算法 JSON 使用 `rho`，runner 将其对应到实际模块，主配置的统一 `seed` 传给优化器；内部 `ResidualOptimizationConfig` 保留 `rho_by_layer`、`beta`、`learning_rate`、`max_steps`、`checkpoints`、`microbatch_size`、`residual_dtype`、`seed` 八项参数。优化器仍为原有 Adam，返回最佳 R、目标值轨迹和最佳步数，不再导出优化器状态或资源诊断。R 从零开始，Q 与基准权重固定，跨层梯度和原有候选选择规则保持；推理缓存转为可反传张量的功能继续保留。

JSON 的 `optimization_steps`、`selection_steps` 分别对应内部 max_steps、checkpoints；数据 JSON 的 keep_dev_fraction、keep_test_fraction 对应输入准备的 dev_fraction、test_fraction。只调整外部名称，内部数值计算不变。仅支持 edit_probe 的策略字段从 JSON 移除，继续使用代码默认规则。

合并参数 `alphas`、`delta`、`tau_g`、`tau_u`、`epsilon`、`equivalence_atol`、`equivalence_rtol`、`chunk_size` 直接位于算法 JSON 顶层；内部 `AcceptanceConfig` 另保留默认的 `compute_dtype`，默认值和原试步顺序不变。开发编辑仍使用全 mask 短答案输入，按事实、同事实探针和 token 均分；协议直接体现在 `development_edits` 中，旧 `edit_protocol` 标记已移除。开发保持始终执行完整词表 KL(theta_0 || theta_alpha)，U 从实际存储权重计算相对最初 W_0 的累计净变化。

P5 已移除参数版本/摘要/别名扫描、辅助 V* 与公式（14）的运行时诊断、配置检查和附带阶段报告的异常包装。每次实际写回仍只覆盖选定目标权重，拒绝或运行异常时恢复 W_b；非有限试步、同 α 前向不一致、三个开发门槛不通过的选择行为保留。正常接受/拒绝的逐试步结果结构不变，运行异常恢复后直接上抛，由 runner 记录运行失败。

`runner.reference_examples` 在首次编辑前调用，训练和开发保持输入分别计算最初 θ₀ 的完整词表 log 概率。同文件中的 `edit_round` 消费已采集轨迹，不重新采样；逐层计算 C 并立即求 Q，退出候选上下文后才实际合并，未选出 R 时直接结束本轮。数据划分、轨迹采样、W₀ 缓存和独立/连续编辑控制均由 runner 调度。

统一随机种子只在 `configs/main.json` 设置。runner 把相同的 `seed` 传入保持题摘要划分、轨迹采样与残差优化，默认 `2026`，并写入运行摘要；派生事实种子、摘要排序和优化器自身的计算保持原实现。

runner 按既定数据与配置格式执行，源码不使用显式 raise/assert。文件、字段及张量错误沿用底层库原生异常；算法必需的语义约束用 sys.exit(原因) 非零退出，finally 保存 failed 摘要并恢复状态。默认配置、设备优先级、resident 精度设置、C/Q 计算设备及保持分批规则均不变。输入格式和语义应在准备正式实验数据时满足，运行器不负责独立的数据审核。

`model/base.py` 的 `MaskedEditInput` 保存模型输入；`MDLM/states.py` 的 `EditTarget` 单独保存监督答案，`DenoiseTrace` 在内存中保存前向前状态、原始 logits 摘要、揭示记录和终态。适配器的 `ForwardCapture` 返回位置矩阵；states 的 `capture_edit` 选主体末位置并取出单个键向量。`util/nethook.py` 的 `TargetWeightSnapshot` 简化为目标模块名到 CPU 权重副本的字典，用于原位恢复本轮 W_b；runner 的 originals 则是公式（17）的固定 W₀。轨迹数据容器的字段与比较规则保留，张量摘要仍按原 header 和原始字节计算 SHA-256。

共享接口支持现行 LLaDA 的隐式连续位置和等长批量输入，没有显式时间或分块字段。`render_prompt` 提供模型模板；`target_module_names`/`inspect_target_modules` 提供真实层名与维度；`forward_with_capture(model, requests, module_names=...)` 接收 `(模型输入, 捕获位置)` 请求；`forward_logits` 保留计算图；快照/恢复委托通用工具。模型加载仍由具体适配器实现。注册工厂当前默认 LLaDA，新增适配器仍需验证模型与 MDLM 的适用条件。

LLaDA 的单条与等长批量捕获共用 `_forward_capture`，由 `util.nethook.capture_inputs` 安装 pre-hook、复制指定位置并记录调用次数，退出时只移除本次 hook。`_forward` 统一构造 token/attention 张量、关闭 KV cache 并读取原位置完整词表 logits；捕获用 no_grad，可微读出由调用方控制梯度。单条激活字典沿用实际调用顺序，批量沿用请求的层序。`keep_matrices` 按适配器层名逐层请求捕获，不再硬编码 LLaDA 路径或为每层重建适配器；C 的分批顺序与逐层释放不变。

`MDLM.states.sample_denoise` 保留原受控窗口策略：目标仅用于构造窗口长度及随后监督，采样不接收目标 token；原始 logits 先计算摘要，再在 float32 副本中屏蔽特殊 token，按温度选择普通 token，以预测置信度排序并逐步揭示。前向前状态进入内存轨迹，终态单列，不重新掩码。该采样配方服务公式（1），没有独立公式编号；它不是公式（2）的完整词表监督分布。本次没有修改采样策略，也未执行完整 8B 实验。

`MDLM.states.prepare_inputs` 接收完整数据集，按 `strip(prompt)` 的摘要去重并保留首次原始题目/答案，再按 seed 和题目摘要的联合摘要排序。原比例计数决定互斥的 `dev`、`test`、`statistics_train`；`test` 仅保留题目摘要，不编码或执行评价。编码先训练后开发：C 捕获模板化提示末 token 与答案 mask，位置权重为 scale/(训练题数×该题捕获位置数)；训练/开发 KL 仅读答案 mask，权重为 1/(各组题数×该题 mask 数)。保持答案仅确定稳定窗口，不作为 KL 标签；最初 θ₀ 分布由 runner/reference_examples 提供。统计与训练复用同一训练输入，开发保持使用独立分区。

代码的 edit_probe 规则直接返回各案例的 edit 探针，开发编辑会复用训练所用的题目；保持分区隔离不能解释为编辑开发题也已独立留出。开发保持题不用于 C/保持训练，而用于原有接受门槛；额外 test 保持题不用于训练或候选选择，当前仅保留划分。摘要划分只保证当前题目键互斥，不负责语义、来源或 tokenizer 归一化后的跨用途隔离。原题目来源、全 mask 窗口、捕获位置、均分权重、分区比例和编码顺序保留，移除手写错误检查。

`align_edit_prompt` 接收已套聊天模板的提示，用字符串 index 定位主体字符区间，再按相交的非空 offset 找主体 token。提示和“提示+答案”各分词一次，按提示长度截取监督答案；主体唯一性、偏移覆盖、普通答案 token 和稳定前缀属于输入约定，不再运行重复校验。states 从提示 token 数起构造等长全 mask 窗口，答案单独进入 EditTarget，主体最后位置供公式（4）取键；保持输入仍由 encode_keep 单独构造。

`adapt_reviewed_cases` 保留源案例与请求顺序，将 edit_requests 与 edit_questions 按下标配对。单请求沿用源 case_id，多请求使用 request_id，同时保留 source_case_id/source_request_id；runner 据共同来源分组联合编辑。fact_core.new_object 来自 experimental_new_answer，实际监督来自编辑题 expected_new_answer；当前转换不核对二者一致性或题目关系，依赖源数据审核。gold_ready 沿用原真值判断，review_status 仅复制。独立测试题不进入输出，free_form_qa/portability 保持为空；旧版阅读清单中的评价题转换/生成视图描述不适用于当前链路。保持题仅挂在首个事实，prepare_inputs 仍读取完整转换集，因此按事实筛选不会丢失该源案例的保持题。

runner 通过 `load_dataset` 选择 native 或四类外部读取器，得到 cases、可选 keep_pool 和读取元信息。native 默认仍调用原 `load_cases`：读取 UTF-8 文件，精确的 .jsonl 后缀逐非空行解析，其他后缀整文件解析；数组保留，单对象包装成列表，仅首条同时含 edit_requests/edit_questions 时调用审核源转换。普通运行格式原样返回，不按 split 或 example_only 自动筛除。case_purpose 暂无正式调用方，其旧判定保持不变。native 设置 source_limit 后按源记录限量再展开。

外部读取器使用 ijson 流式读取 JSON 或逐行读取 JSONL，保留源顺序、编辑答案及用途分组，不迁移 UltraEdit 的自回归 labels。所有原始数据文件只读。source_limit/keep_limit 控制读取规模，case_ids/max_cases 控制实际编辑范围；每条记录对应独立源案例，完整 ID 由读取器、文件名和源 ID/下标组成。FEVER 主体缺失可以通过 subject_path 标注文件补充，在实际编辑输入构造时检查主体唯一性和精确 token 对齐。改写、persona、多跳问题不参与编辑监督，可由独立评价入口使用。字段和配置说明见[可选数据读取器](../配置参数说明.md#可选数据读取器)。

`prepare_inputs` 新增可选 keep_pool 参数：未传入时继续读取完整案例集的 preservation；传入时用显式池替换来源。之后的去重、固定分区、编码顺序和位置权重均沿用原实现。运行摘要新增 dataset_reading，记录读取路径、参数和数量；不写转换数据文件。

`execution_context` 包围 runner 的完整算法运行。配置为 resident 时关闭矩阵乘法和 cuDNN 的 TF32，结束或异常退出后恢复进入前的两个开关；显式 CUDA 设备会被设为当前设备。它不负责移动模型、不创建推理/反传上下文，也不恢复进入前的当前 CUDA 设备。`backend=subprocess` 仅保留旧精度语义，当前仍是单进程运行。该工具不直接实现公式（1）～（18），只是固定共同的设备和浮点环境。

`util/io.py` 不是数据集读取器：`read_json` 读取 JSON，`read_config` 组合主配置及模型/数据集/算法的直接引用，`write_json` 保存运行摘要及模型元数据；数据集由 `data/dataset.py` 负责。`config_digest` 对紧凑、键排序的 UTF-8 JSON 计算 SHA-256，供 prepare_inputs 去重和按 seed 稳定排序，因此间接固定公式（5）（10）（16）的保持输入集合，但摘要计算本身没有算法公式编号。 `project_path` 继续按项目根解析资源路径，`choose_run_id` 继续按命令行、配置、时间戳与 UUID 的优先级选择运行目录名。

## 输出与重载

已建立的运行目录 `runs/<run_id>/` 会写入 `run_report.json`。独立模式仅为被接受的案例创建 `case_<index>/`；连续模式在全部轮次结束后创建一个 `final_model/`。每个最终模型目录只有 `model.json` 和 `target_weights.safetensors`，保存目标层的最终权重；重新加载时还需要 `model.json` 所记录的原始模型路径。

```python
from MDLM.runner import load_final_model

adapter, model = load_final_model("runs/<run_id>/final_model", device_map="cuda:0")
```

运行时不会保存各阶段的轨迹、$K/C/Q/R$、优化器状态或阶段清单。旧 `runs/` 中的这些文件若仍存在，属于历史运行结果。`--cache-dir`、`--no-cache` 已移除，评估代码也不在当前算法运行链路中。数据集与原始模型目录都由配置或命令行指定，仓库不上传其大文件。

最终权重直接按原精度保存和覆盖。原 workflow 的四个函数已并入 runner，不再保留旧模块；输出文件名、metadata、函数签名及正常返回结果不变。最终结果仍依赖原始模型目录，保存的是最终目标权重，不是待重复相加的增量。
