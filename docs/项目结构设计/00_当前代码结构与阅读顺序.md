# 当前代码结构与阅读顺序

更新：2026-10-29。本文对应当前 `main` 分支的内存运行流程。数学定义仍以[《最终逻辑 V1.0》](../最终逻辑%20V1.0.md)为准；旧版分阶段开发记录保留在其他文档中，所列阶段命令与产物目录不再是当前运行方式。

## 运行方式

```bash
conda activate mdlm
python -u main.py --editor mdlm --config configs/full_run.json
```

`main.py` 解析参数，按 `--editor` 选择并按需导入算法。MDLM 的实际流程在 `MDLM/runner.py`：读取案例和配置、准备保持输入、加载一次模型，然后按源案例执行编辑。`--case-id` 可选一个或多个源案例/事实；默认各源案例独立编辑，`--sequential` 只把已接受的权重留给下一案例。保持输入始终由完整数据集确定，案例筛选只决定编辑对象，不改变确定性划分。

同一源案例下的所选事实联合编辑，案例与事实顺序沿用数据集；按事实编号筛选时只编辑该事实。连续模式在某案例被拒绝后，保留上一接受模型并继续处理后续案例。此循环是跨案例实验方式，与《最终逻辑 V1.0》11.1 中“同一事实集最多刷新一次”的外轮不同；当前入口不执行该刷新，也不执行独立生成评价。

每轮在内存中依次执行：

```text
审核后的案例 → P1 去噪轨迹与监督 → P2 参考键 K、保持统计 C
             → P3 固定写回因子 Q → P4 优化残差 R
             → P5 合并、开发集门槛、接受或精确回退
```

P0 是运行前的数据、模型和适配器边界检查。独立的 `util/smoke_p0_llada.py` 可用于手工检查真实模型；统一入口不调用旧的逐阶段命令。

## 现行文件职责

| 位置 | 职责 |
| --- | --- |
| `main.py` | 统一命令行入口和 `--editor` 算法注册表。 |
| `MDLM/runner.py` | 四个函数负责项目路径、输出目录名、案例筛选、实验运行；加载一次模型，固定最初 θ₀/W₀，控制独立/连续编辑与本轮恢复。 |
| `MDLM/states.py` | 去噪轨迹筛选、兼容状态、事实/状态/位置三级监督权重。 |
| `MDLM/keep_statistics.py` | 公式（5）的未中心化加权二阶矩 $C$ 累计，不生成诊断报告。 |
| `MDLM/writeback.py` | `WritebackConfig`、公式（6）～（9）的固定 $Q$ 求解；另保留其他模块共用的 Frobenius 范数计算。 |
| `MDLM/candidate.py`、`MDLM/optimize.py` | 全位置 $R(Qk)$ 分支、固定 Q 的多层 R 联合优化、预定检查点中的最佳候选；仅保留目标值轨迹和最佳步数。 |
| `MDLM/merge.py`、`MDLM/acceptance.py` | 固定 ΔW=RQ、从 W_b 重建公共 α 试步、因子/实际合并前向一致性、三个独立开发门槛与精确回退。 |
| `MDLM/workflow.py` | 四个函数：最初 θ₀ 的完整词表保持参考、单轮监督 → K/C → Q → R → 接受、最终目标权重保存和重载。 |
| `model/base.py`、`model/registry.py`、`model/adapters/llada_8b_instruct.py` | 模型输入与轨迹接口、适配器选择、LLaDA 前向/捕获/采样/权重操作。 |
| `data/readers/`、`data/validation/alignment.py`、`data/schema.py` | 读取已审核案例、转换源案例、token 对齐；`schema.py` 供单独数据检查。 |
| `util/prepare_dataset_inputs.py` | 内存中准备保持统计、保持训练、开发保持和开发编辑探针。 |
| `util/collect_denoise_states.py`、`util/extract_reference_keys.py` | 采集去噪轨迹、从初始全 mask 状态提取 $K$ 并重放核对。 |
| `util/extract_keep_statistics.py` | 每批保持输入只前向一次，逐层返回模块名和 $C$；用于求出该层 $Q$ 后即可释放。 |
| `util/gpu_runtime.py`、`util/io.py` | 运行精度/设备上下文、JSON 读写和确定性输入划分摘要。 |
| `configs/full_run.template.json`、`configs/full_run.json` | 当前全流程参数模板和默认配置；其中 `p1`～`p5` 控制对应算法步骤。 |

`MDLM/contracts.py` 和旧的逐阶段磁盘入口已经删除；独立的 P0 冒烟脚本仍保留。数值参数类位于对应算法模块。`configs/*_example_only.json` 是旧逐阶段技术联调留下的示例，不作为 `main.py` 的全流程配置。`tests/` 只在本地保留，由 `.gitignore` 排除。

保持统计的运行时诊断、重复前向和独立重放已移除，原辅助文件 `util/validate_matrix_artifacts.py` 已删除。`p2_keep` 只接受 `accumulation_dtype`、`storage_dtype`、`device`、`batch_keep`，默认配置中的空字典继续适用。公式（5）的数学对照和修改前后数值回归放在本地测试中。

写回求解直接返回 CPU 上的固定 Q，不再返回诊断报告。`p3` 只接受 `ridge_by_layer`、`compute_dtype`、`storage_dtype`、`device`，默认配置继续适用；旧的检查容差、分块诊断和失败策略参数已移除。写回公式与修改前后数值对照在本地测试中验证。

`p4` 保留 `rho_by_layer`、`beta`、`learning_rate`、`max_steps`、`checkpoints`、`microbatch_size`、`residual_dtype`、`seed` 八项参数。优化器仍为原有 Adam，返回最佳 R、目标值轨迹和最佳步数，不再导出优化器状态或资源诊断。R 从零开始，Q 与基准权重固定，跨层梯度和原有候选选择规则保持；推理缓存转为可反传张量的功能继续保留。

`p5` 保留 `alphas`、`delta`、`tau_g`、`tau_u`、`epsilon`、`compute_dtype`、`equivalence_atol`、`equivalence_rtol`、`chunk_size` 九项参数，默认值和原试步顺序不变。开发编辑仍使用全 mask 短答案输入，按事实、同事实探针和 token 均分；协议直接体现在 `development_edits` 中，旧 `edit_protocol` 标记已移除。开发保持始终执行完整词表 KL(theta_0 || theta_alpha)，U 从实际存储权重计算相对最初 W_0 的累计净变化。

P5 已移除参数版本/摘要/别名扫描、辅助 V* 与公式（14）的运行时诊断、配置检查和附带阶段报告的异常包装。每次实际写回仍只覆盖选定目标权重，拒绝或运行异常时恢复 W_b；非有限试步、同 α 前向不一致、三个开发门槛不通过的选择行为保留。正常接受/拒绝的逐试步结果结构不变，运行异常恢复后直接上抛，由 runner 记录运行失败。

`workflow.reference_examples` 由 runner 在首次编辑前调用，训练和开发保持输入分别计算最初 θ₀ 的完整词表 log 概率。`edit_round` 消费已采集轨迹，不重新采样；逐层计算 C 并立即求 Q，退出候选上下文后才实际合并，未选出 R 时直接结束本轮。数据划分、轨迹采样、W₀ 缓存和独立/连续编辑控制均由 runner 负责。

runner 已合并重复的设备选择分支，并移除层编号、输入模式、example-only 标签、事实 ID 唯一性、整模型 GPU 驻留扫描及加载后重复目标层检查。它按既定数据与配置格式执行；不再由入口阻止这些非法或示例输入，不能把示例运行当作正式算法效果。模型适配器、输入准备和采样自身的检查不变。目录名边界、指定案例不存在时的报错、异常恢复和运行摘要保留；默认配置、设备优先级、resident 精度设置、C/Q 计算设备及保持分批规则均不变。

## 输出与重载

已建立的运行目录 `runs/<run_id>/` 会写入 `run_report.json`。独立模式仅为被接受的案例创建 `case_<index>/`；连续模式在全部轮次结束后创建一个 `final_model/`。每个最终模型目录只有 `model.json` 和 `target_weights.safetensors`，保存目标层的最终权重；重新加载时还需要 `model.json` 所记录的原始模型路径。

```python
from MDLM.workflow import load_final_model

adapter, model = load_final_model("runs/<run_id>/final_model", device_map="cuda:0")
```

运行时不会保存各阶段的轨迹、$K/C/Q/R$、优化器状态或阶段清单。旧 `runs/` 中的这些文件若仍存在，属于历史运行结果。`--cache-dir`、`--no-cache` 已移除，评估代码也不在当前算法运行链路中。数据集与原始模型目录都由配置或命令行指定，仓库不上传其大文件。

最终权重直接按原精度保存和覆盖，workflow 已移除保存后立即读回、加载时额外的目标层检查/整层快照/回滚，以及保持参考和阶段连接的重复检查。文件名、metadata、函数签名及正常返回结果不变；最终结果仍依赖原始模型目录，保存的是最终目标权重，不是待重复相加的增量。

## 建议逐文件阅读

1. `README.md` → `main.py` → `configs/full_run.template.json` → `MDLM/runner.py`：先看启动参数、选例、模型加载和轮次边界。
2. `data/readers/reviewed_cases.py` → `data/readers/json_cases.py` → `data/validation/alignment.py` → `model/base.py` → `model/registry.py` → `model/adapters/llada_8b_instruct.py`：确认案例、token 与模型接口。
3. `util/prepare_dataset_inputs.py` → `util/collect_denoise_states.py` → `MDLM/states.py`：理解输入划分、无答案采样和监督权重。
4. `util/extract_reference_keys.py` → `MDLM/keep_statistics.py` → `util/extract_keep_statistics.py`：理解 $K/C$ 的捕获位置、显式权重、累计精度和逐层计算。
5. `MDLM/writeback.py` → `MDLM/candidate.py` → `MDLM/optimize.py`：核对固定 $Q$、临时分支与 $R$ 优化。
6. `MDLM/merge.py` → `MDLM/acceptance.py` → `MDLM/workflow.py`：核对公共步长、开发门槛、回退和最终结果重载。
7. `util/gpu_runtime.py` → `util/io.py` → 回看 `MDLM/runner.py`：检查执行精度、结果目录和异常处理。

算法定义和代码实现要区分：历史阶段文档记录了旧版开发与技术联调证据，不能据此推断当前版本已经完成正式 8B、多事实、多层实验。
