状态：P0–P5 核心代码与相应审核已完成；P5 专项审核修复权重/精度、U 和重载缺口，新增 12 项，P5 58 项/全套 242 项通过。原真实单案例证据保留，仍为 example_only、p5_stage_complete=false。正式数据、保持配方、逐层参数、真实多事实/多层及 β>0 8B 验收待完成；P6 待实现，用户个人阅读另行记录。本文是对[《扩散知识编辑算法开发方案 V1.0》](../扩散知识编辑算法开发方案%20V1.0.md)的目录设计；数学和阶段门槛以[《最终逻辑 V1.0》](../最终逻辑%20V1.0.md)及开发方案为准。

## 1. 结构目标与参考

[MEMIT 官方仓库](https://github.com/kmeng01/memit)把算法、数据、实验、超参数和工具分开，并让[实验入口](https://github.com/kmeng01/memit/blob/main/experiments/evaluate.py)调用[算法实现](https://github.com/kmeng01/memit/blob/main/memit/memit_main.py)。本项目参考这种清晰的职责划分，再按实际主算法增加去噪状态、矩阵提取、联合残差优化、验收回退与独立生成评价。MEMIT 的自回归输入和具体更新公式不能直接替代本项目的扩散模型逻辑。

根目录下的 `MDLM/` 承载算法与共享合同；`model/` 管理原始模型及适配代码；`data/` 管理可信数据读取和独立校验；`util/` 放阶段命令入口，调用提取、Q/R 和 P5 合并验收。`tests/` 覆盖 P0–P5；`evaluation/` 仍为空。中间产物统一归入 `runs/`，`configs/` 提供各阶段示例，正式实验配置仍待冻结。

## 3. 各目录的唯一职责

| 目录 | 放什么 | 边界 |
| --- | --- | --- |
| `MDLM/` | 算法公式、状态监督、$Q$ 求解、$R$ 优化、权重合并、验收流程 | 不保存原始权重或原始数据；不直接调用外部裁判 |
| `model/models/` | 原始模型权重、Tokenizer 与原模型配置，或其受控路径说明 | 不放编辑后的模型；不提交大权重 |
| `model/adapters/` | 每个原始模型的加载、编码、mask、单步前向、logit 位置和目标模块定位 | 对外统一适配接口；LLaDA 已编写 P1 自主去噪，目标答案不进入采样器 |
| `data/datasets/` | 来源可追溯的原始数据、处理版和划分 | 原始文件不覆盖；训练、开发、测试用途分开 |
| `data/readers/`、`data/validation/` | 读取预先审核的数据、提取评价输入和完成模型 token 对齐 | 算法运行时不执行数据集质量检查 |
| `util/` | P0–P4 的独立命令入口、提取与验收编排 | Q/R 数学实现在 `MDLM/`；入口不复制公式，不合并权重 |
| `evaluation/` | 当前只保留空目录；为后续独立评估实现预留位置 | 此阶段不放文件或子目录；裁判不进入训练梯度 |
| `tests/` | 人工小例、接口和后续数值验证 | 当前 P0 字符级 tokenizer 仅检查契约，不代替真实 tokenizer/模型实验 |
| `configs/` | 模型、数据、提取、编辑和评价配置 | 使用清晰文件名区分，不存密钥或机器私有路径 |
| `runs/` | 冻结配置、固定状态、$K/C/Q$、QA、$R$ 检查点、接受/回退、生成与评价结果 | 按运行和轮次隔离，保留失败记录，不覆盖旧运行 |

`MDLM/`、`model/`、`data/` 作为 Python 包；`util/` 提供 P0–P5 独立命令，P4 数学在 candidate/optimize，P5 数学在 merge/acceptance，workflow 绑定同轮产物并编排 P5。P1～P4 仍按既有独立入口运行，当前不自动刷新外轮。`MDLM` 使用大写包名，运行命令从项目根目录或安装环境执行，避免临时修改 `sys.path`。

## 4. `MDLM/` 算法包内部划分

`MDLM/` 内不再创建子文件夹。首版用以下同级文件表达算法步骤；若某文件以后确实过大，再依据实际维护需要拆分。

```text
MDLM/
├── __init__.py
├── contracts.py                         # 配置、产物引用、形状/有限性约束
├── states.py                            # 公式（1）～（3），兼容筛选与 F
├── keep_statistics.py                   # 公式（5），CPU 流式二阶矩与块数值诊断
├── writeback.py                         # 公式（6）～（9），H X=K、Q=Xᵀ
├── candidate.py                         # 公式（11），真实多层候选前向
├── optimize.py                          # 公式（10）（12），J(R) 与 R 优化
├── merge.py                             # 公式（13）～（15），实际 ΔW 和合并
├── acceptance.py                        # 公式（16）～（18），三门槛与回退
└── workflow.py                          # 串接已验收产物与单轮主算法
```

`contracts.py` 只定义共享结构与不变量，`workflow.py` 只控制阶段顺序；数学实现在各自文件中。`writeback.py` 的 $Q$ 是给定 $K,C,\lambda$ 的固定写回因子，`optimize.py` 的 $R$ 是随后在真实候选模型上优化的变量。`acceptance.py` 中 $G_{\mathrm{dev}}$ 与 $U$ 始终以最初模型 $\theta_0/W_0$ 为参照。

`MDLM/contracts.py` 已实现 P1–P5 配置、文件摘要与运行标识；states 实现公式（1）～（3），keep_statistics 实现公式（5），writeback 实现公式（6）～（9），candidate/optimize 实现公式（10）～（12），merge/acceptance 实现公式（13）～（18）。workflow 只编排已验收 P4 候选的单轮 P5 与实际模型重载；各阶段独立入口位于 `util/`。

| 2 | `model/base.py`：`KeepModelInput`；`model/adapters/llada_8b_instruct.py`：`forward_keep_with_capture` | 完整保持输入、显式位置 → logits 与各位置真实 `ff_out` 输入；支持上下文和 mask 位置，保持原编辑接口的主体单向量语义。 |
| 3 | `MDLM/keep_statistics.py`：`SecondMomentAccumulator.add/diagnose` | 激活 `[n,d_in]` 与逐位置权重 → 未中心化 $C=\sum\omega uu^\top$ 与块 QA；以 $v=\sqrt\omega u$ 等价累计并计算独立参考，避免中间溢出/下溢；CPU 累计，不归一、不加 ridge，不保存全部激活。 |
| 4 | `util/extract_keep_statistics.py`：`extract_run` | 同轮 P1/K、冻结保持输入和配置 → 每层 C、完整输入副本、来源清单和 QA；逐层重放，磁盘分块读回明确核对 dtype、形状和数值。 |
| 5 | `util/smoke_p2_keep.py`：`freeze_example_inputs/main` | `--layer 0` 新建 P0/P1/K/C 联调；`--p1-dir` 复用同轮 P1/K 仅做 C；读取原始配方前记录 SHA，冻结结束复查，输出示例技术验收报告。 |
| 6 | `tests/test_keep_capture.py`、`test_keep_statistics_math.py`、`test_keep_statistics_pipeline.py`、`test_p2_keep_smoke.py` | 44 项轻量检查：8 项捕获、17 项数学、12 项链路、7 项入口；新增覆盖极端 C、近零投影、小坐标保护、3000×32 批量差异、严格 JSON、保存数值/dtype、存储溢出和基准 logits。 |

保持输入单独记录统计用途、来源、mask 配方、捕获位置与每层显式非负权重；不自动把编辑轨迹、开发保持题或独立测试题作为统计语料。示例使用两条独立人工输入，各捕获两个位置，原始权重含零且总量不要求为 1。正式语料、mask、位置、权重和尺度仍待冻结；示例不替代正式方案。

数值诊断分块检查有限性、对称性、对角及 trace，并核对独立小坐标外积和投影二阶矩。小坐标使用 $\sqrt{E_{ii}}\sqrt{E_{jj}}$ 元素尺度，投影和 PSD 使用 trace 能量尺度；冻结 atol/rtol 不变。P2-03 重新捕获冻结输入并使用另一组投影和坐标独立复算。只对低维投影计算特征值，明确不宣称完整谱证明。正式保持配方尚未冻结；代码与示例技术验收完成不代表正式阶段验收通过。

## 5. 从提取到评估的依赖与开发顺序

```text
configs + model + data
           ↓
util：采集完整状态 → 筛选兼容状态 → 提取 K、C → QA
           ↓（产物通过、基准/事实顺序一致）
MDLM.writeback：求解 Q
           ↓
MDLM.candidate + MDLM.optimize：真实候选前向、J(R)、联合优化 R
           ↓
MDLM.merge + MDLM.acceptance：ΔW=RQ、合并、公共试步、验收/回退
           ↓
evaluation：固定最终模型的独立自由生成与裁判
```

| 阶段 | 主要归属 | 输入与可检查输出 |
| --- | --- | --- |
| P0 | `model/`、`data/`、`configs/` | 原始模型适配、真实 tokenizer/位置对齐、案例用途清单 |
| P1 | `util/collect_denoise_states.py`、`util/filter_compatible_states.py`、`MDLM/states.py` | 完整自主状态、兼容状态、固定监督权重 |
| P2 | `util/extract_reference_keys.py`、`util/extract_keep_statistics.py`、`util/validate_matrix_artifacts.py` | 同轮同基准的 $K,C$ 与 QA 报告；这是算法开发前的阶段门槛 |
| P3 | `MDLM/writeback.py`；当前由 `util/solve_writeback_factor.py` 调用，未来接入 workflow | 固定 $Q$、线性求解残差和数值报告 |
| P4 | `MDLM/candidate.py`、`MDLM/optimize.py`，当前由 `util/optimize_residuals.py` 调用 | 合格 $R^*$、同一步优化器状态或明确失败记录 |
| P5 | `MDLM/merge.py`、`MDLM/acceptance.py`，由 `MDLM/workflow.py` 调用 | 接受的实际模型或恢复基准的回退记录 |
| P6 | `evaluation/`（当前预留为空） | 后续独立生成、裁判与覆盖率报告 |

P0 从 `data/` 读取可信案例并完成 token 对齐；独立 `data/schema.py` 仅供手动质量检查。P1/P2 从 `util/` 启动提取；P3 的独立入口调用 `MDLM.writeback`，只读取 complete 的 P2 矩阵包。未来 P3～P5 由 `MDLM/workflow.py` 统一编排；workflow 负责来源、阶段、记录和回退，不复制数学实现。

## 6. 运行产物与配置约定

```text
runs/<run_id>/
├── config.lock.*                       # 后续规划：完整实验冻结配置
├── round_<n>/
│   ├── p1/                             # 当前已实现的 P1 产物目录
│   │   ├── manifest.json               # p1.1 配置、来源摘要、事实顺序与重放选择
│   │   ├── trajectories.jsonl          # 完整前向前状态、揭示 token、logits 摘要与终态
│   │   ├── collection_report.json      # 采集/重放结果或失败原因
│   │   ├── fixed_states.jsonl          # 通过公式核验后生成的固定监督
│   │   └── coverage_report.json        # 覆盖、权重核验或筛选失败原因
│   ├── matrices/
│   │   ├── reference_keys/             # 当前已实现：公式（4）的 K
│   │   │   ├── keys.safetensors         # 完整模块名 → d_in × N 张量
│   │   │   ├── manifest.json            # p2.keys.1 基准、来源、列序、精度与文件摘要
│   │   │   └── qa_report.json           # 初态 logits、逐列复提、磁盘往返或失败诊断
│   │   ├── keep_statistics/            # 当前已实现：公式（5）的 C
│   │   │   ├── c_layer_<l>.safetensors  # 每层独立文件：完整模块名 → d_in × d_in
│   │   │   ├── keep_inputs.json         # 完整保持 token/注意力/mask/位置及每层权重副本
│   │   │   ├── manifest.json            # p2.keep_statistics.1；同轮 P1/K、配方和文件摘要
│   │   │   └── qa_report.json           # 捕获重放、块数值 QA、磁盘往返或失败阶段
│   │   ├── validation/                 # 当前已实现：P2-03 统一矩阵包验收
│   │   │   ├── manifest.json            # p2.matrix_bundle.1 来源、示例标记与完成状态
│   │   │   └── qa_report.json           # 真实重放和独立矩阵复算结果
│   │   └── writeback_factors/          # 当前已实现：P3 固定 Q
│   │       ├── q_layer_<l>.safetensors  # 每层 N × d_in 固定因子
│   │       ├── manifest.json            # p3.writeback_factor.2 同轮来源、λ 与精度
│   │       └── qa_report.json           # 分解、HX=K/QH=Kᵀ 残差、资源或失败原因
│   ├── keep_inputs.json                # 联调入口冻结的独立保持输入配方
│   ├── p2_keep_acceptance_report.json  # P0/P1/K/C/P2-QA 联调总报告
│   ├── p3_writeback_acceptance_report.json # P3 示例技术验收总报告
│   ├── p3_writeback_review_report.json  # 本轮 CPU 审核复算报告，保留旧 Q 及版本 1 清单
│   ├── residuals/                      # 当前 P4 输出，旧成功/失败目录均不覆盖
│   │   ├── manifest.json               # p4.residual_candidate.2 来源、固定参数及候选状态
│   │   ├── optimization_report.json    # J 各项、梯度/R/RQ 范数、资源及失败阶段
│   │   ├── residuals.safetensors       # 合格候选：各层 d_out × N
│   │   ├── optimizer_state.pt          # 与所选 R 同一步的 Adam 状态
│   │   └── theta0_keep_log_probs.safetensors # 仅 β>0，最初模型完整词表参考缓存
│   ├── p4_candidate_acceptance_report.json # P4 技术验收报告，示例仍标记未正式完成
│   ├── residuals_review_v2/             # 本轮复验新目录，结构同 residuals，保留旧版本 1
│   ├── p4_candidate_review_report.json  # 版本 2 真实复验及新旧产物对照
│   └── editing/                        # P5：α 试步及开发验收记录（冒烟下为 p5_smoke/configured 等）
│       ├── manifest.json               # p5.merged_model.2，accepted/rejected/failed
│       ├── acceptance_report.json      # 逐 α 的等价/三门槛与恢复诊断
│       ├── development_inputs.json     # 原案例提取的全 mask 开发编辑与独立保持输入
│       ├── theta0_target_weights.safetensors # 最初 W_0 的目标层快照
│       ├── theta0_keep_log_probs.safetensors # 最初模型完整词表参考
│       ├── candidate_increments.safetensors # 公式（13）的 RQ
│       ├── final_target_weights.safetensors # 接受后的实际目标权重或恢复的 W_b
│       └── final_dev_logits.safetensors # 无因子最终前向，供磁盘重载复核
├── final_model/                        # 已接受模型或可核验的增量引用
├── generations/                        # 独立输入及完整回答
├── judgments/                          # 裁判原始和结构化结果
└── reports/                            # 指标、失败与覆盖率
```

每个矩阵保存层名、维度、dtype、事实列序、模型修订、本轮基准摘要、统计配方及校验和；`K`、`C`、`Q` 通过同一轮清单关联，不能只按文件名配对。第二轮刷新须创建新 `round_<n>` 并重新采集状态、$K,C,Q$；$\theta_0/W_0$ 引用保持不变。`data/datasets/<name>/raw/` 始终保留原始快照；处理数据和切分要有版本。`runs/` 下的子目录由实际运行按需生成，目前不预建。

P1–P4 入口均核对算法产物来源；K 匹配 P1 初态，C 绑定同轮 K 和保持输入，P2-QA 完成真实重放与独立矩阵检查，P3 绑定固定 λ，P4 绑定固定 Q/ρ/预算及可选最初模型参照。失败目录保留，仅 complete 清单可供后续使用。输入数据质量仍由独立工具负责。

P4 的保持训练新增独立 token 合同 `p4.keep_training.1`（`purpose=keep_train`），不改变案例 JSON；显式保存完整输入、读出位置和总和为 1 的权重。β=0 不读取训练保持文件；开发保持与测试用途在运行前独立审核。详细合同、命令和正式验收边界见 README 与 02 文档。P4 阅读清单见 03 文档 CR-032～039。

P4 审核后复用 `MDLM/writeback.py` 公开的 `stable_frobenius_norm`，P3 原求解计算不变。正则使用 float64 等价加权平方；来源清单还绑定实际模型/Tokenizer、theta_0 与参考缓存。R/Adam 状态均读回核对，候选按模块恢复模式且可重复清理。直接优化入口允许指定新的 `--output-dir` 复验目录；失败和历史结果不覆盖。

P5 开发保持新增独立计算合同 `p5.keep_development.1`（purpose=keep_dev），不更改案例 JSON。开发编辑由显式探针选择，冻结 `full_mask_mean_fact_probe_token_v1`；详情见 README。`load_final_model` 从不可变基准加最终实际目标权重重建模型，并核对最终 logits，失败恢复已加载实例的目标基准。原示例三检查报告在 `round_0/p5_smoke/p5_acceptance_report.json`，α=0.5 被接受，强制拒绝及重载通过；专项审核已完成，正式实验待验收。

P5 专项审核后 58 项（14 合并/15 门槛/29 流程），默认 CPU 线程下全套 242 项通过。受控写入后记录目标版本/字节摘要，U 采用共同尺度计算有限净比值；重载核对选择记录、完整目标层、增量及实际合并公式，并在前向后复查参数/缓冲区和全部来源。版本 1 历史结果保留，当前加载器要求版本 2，需在新目录复验。公式、超参数、精度配置与容差不变；全部实机证据仍为人工单案例技术联调。

`requirement.txt` 使用既定文件名，未来安装命令为 `pip install -r requirement.txt`。依赖版本在真实环境确认后固定。`.gitignore` 覆盖模型权重、原始/处理数据的大文件、`runs/`、缓存、环境目录和密钥文件；小型配置模板、示例数据、文档和测试样例仍可纳入版本控制。

## 7. 验证与后续扩展

P5 审核后真实复验证据为同轮 `p5_smoke_review_v2/p5_acceptance_report.json` passed：版本 2 仍接受 α=0.5，F_dev/G 不变，U 仅舍入变化；强制拒绝恢复与增强重载校验通过，新旧实际权重文件 SHA-256 一致。原版本 1 目录保留。正式多事实/多层及正式数据验收待补。

`tests/` 当前包含 P0 人工案例和数据/接口检查。后续按实际需要增加状态筛选、矩阵求解、梯度、真实模型捕获、合并一致性及信息隔离检查，不预先创建空的 `unit/`、`integration/`、`numerical/` 子目录。真实模型实验结果单独进入 `runs/`。

首版只为实际需要的原始模型和数据集增加对应脚本，不创建空的模型/数据集子目录作为假支持。以后加入其他编辑基线，可增设 `baselines/`；它应共用 `data/` 的用途划分及 `evaluation/` 的独立评价口径。当前 `docs/算法逻辑/`、`docs/算法计划文档/` 等现有文档保持原位。
