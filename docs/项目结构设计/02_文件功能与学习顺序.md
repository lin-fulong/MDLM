# 文件功能与学习顺序

## 1. 先建立全局概念

按 `README.md` → `docs/最终逻辑 V1.0.md` → `docs/扩散知识编辑算法开发方案 V1.0.md` 阅读。前者告诉你如何运行和当前完成程度；第二份定义公式（1）～（18）；第三份把公式拆成 P0～P6 的实现任务。核心链路是：**案例 → 去噪状态与监督 → 参考键 K、保持统计 C → 固定因子 Q → 优化残差 R → 合并权重并验收**。P6 独立自由生成评价目前只有计划和接入点。

`requirement.txt` 固定当前 LLaDA P0～P5 的运行依赖；`.gitignore` 排除下载模型、数据集、运行产物和临时文件。它们不参与算法计算。

## 2. 读懂输入与模型边界（P0）

1. `data/datasets/cases.jsonl` 是源数据，每行一个已审核格式的案例；`gold_ready` 才会进入正式编辑。`data/readers/reviewed_cases.py` 把源案例的 `edit_requests`、编辑题、保持题及独立测试题转换成程序使用的 `fact_core`/`prompts` 格式；同一源案例的多个编辑请求保留共同来源，供主入口合并成一轮。`data/readers/json_cases.py` 负责读取 JSON/JSONL、识别源格式，并提供不带答案的评价输入。读取与转换不等于重新审核数据。
2. `data/schema.py` 显式校验旧版 `0.3-proposal` 案例结构及答案泄漏，主要供手工案例检查；`data/validation/alignment.py` 确认 subject 和短答案在 tokenizer 中的边界，避免监督位置错位。`data/__init__.py` 仅标记包。
3. `model/base.py` 定义模型输入、答案目标、捕获结果、去噪轨迹和 `ModelAdapter` 接口。关键约束是模型输入不含目标答案。`model/adapters/llada_8b_instruct.py` 实现 LLaDA 的 chat template、全 mask 短答案输入、`ff_out` 激活捕获、去噪采样、logits 读取、目标权重快照与恢复。`model/registry.py` 负责选择适配器；`model/__init__.py` 仅标记包。目前正式流程使用 LLaDA 适配器。
4. `util/smoke_p0_llada.py` 用实际模型检查输入对齐、目标层捕获和重复前向一致性。`tests/fixtures/p0_case_example.json` 是 `example_only` 构造案例，适合联调，不代表正式数据。

## 3. 按阶段读算法实现与执行脚本

| 阶段 | 先读的算法文件 | 再读的执行文件 | 作用与产物 |
| --- | --- | --- | --- |
| 共用 | `MDLM/contracts.py` | `main.py` | 前者冻结配置、模型身份和文件摘要；后者准备输入、按源案例分轮、依次启动阶段并记录报告。`MDLM/__init__.py` 仅标记包。 |
| 输入准备 | — | `util/prepare_dataset_inputs.py`、`util/pipeline_cache.py` | 前者把审核数据分配为保持统计、保持训练、开发保持和保留评价输入，并冻结 token/位置/权重；后者以内容、模型、代码和运行环境建立缓存键，校验缓存文件并归档损坏产物。 |
| P1 | `MDLM/states.py` | `util/collect_denoise_states.py`、`util/filter_compatible_states.py` | 保存完整去噪轨迹，筛出与目标答案兼容的状态，按事实/状态/mask 位置构造固定监督；产物在 `p1/`。后一个脚本也可对已有轨迹单独执行筛选。 |
| P2-K | — | `util/extract_reference_keys.py` | 只从 P1 保存的初始全 mask 输入捕获目标层真实输入，按事实顺序组成参考键矩阵 K，并核对来源和重放。 |
| P2-C | `MDLM/keep_statistics.py` | `util/extract_keep_statistics.py` | 对冻结的保持输入捕获激活，流式累积未中心化加权二阶矩 C；检查数值、配方、模型和 K 的一致性。 |
| P2 验收 | — | `util/validate_matrix_artifacts.py` | 独立核对 P1/K/C 的模型身份、层、列顺序、文件摘要与重放结果，只有完整通过才发布矩阵包。 |
| P3 | `MDLM/writeback.py` | `util/solve_writeback_factor.py` | 从已验收的 K/C 求解固定因子 Q，保存各层数值残差和失败诊断；此阶段不改模型权重。 |
| P4 | `MDLM/candidate.py`、`MDLM/optimize.py` | `util/optimize_residuals.py` | 在真实冻结网络中临时注入 RQ 分支，联合优化多层残差 R；保存最佳检查点、优化记录和残差产物，仍不写入基准权重。 |
| P5 | `MDLM/merge.py`、`MDLM/acceptance.py`、`MDLM/workflow.py` | `util/merge_and_accept.py` | 从同一基准构造各候选步长，实际写权重并检查与临时分支等价；以开发编辑损失、保持 KL 和累计改变量共同判定，失败时恢复基准，成功时保存可重载模型。 |
| 连续编辑 | — | `util/export_edited_checkpoint.py` | 仅在 P5 接受后，把目标权重写成下一轮可加载的本地分片模型；其他分片复用或复制。 |

`configs/full_run.template.json` 是全流程参数模板；`configs/full_run.json` 是当前默认配置。两者设置数据集、模型、目标层、P1～P5 超参数、输入准备和缓存路径。`main.py` 默认逐源案例独立编辑；`sequential` 模式仅把已接受的模型作为下一轮基准。总报告是 `run_report.json`，单轮报告是 `pipeline_report.json`。配置不能代替数据审核，也不能把示例输入用于正式入口。

## 7. 下载模型与运行产物

`model/models/` 下四个目录分别是 `LLaDA-8B-Instruct/`、`Dream-v0-Instruct-7B/`、`LLaDA-MoE-7B-A1B-Instruct/` 和 `iLLaDA-8B-Instruct/`。这些是下载的模型资源，不是本项目的 P0～P5 实现。四者都有各自的 `README.md`（模型卡）、`.gitattributes`、`config.json`（结构参数）、`generation_config.json`（生成默认参数）、`configuration_*.py`（Transformers 配置类）、`modeling_*.py`（模型结构）、`model.safetensors.index.json`（权重分片索引）、`model-*.safetensors`（权重分片）、`special_tokens_map.json`（特殊 token）和 `tokenizer_config.json`（分词器设置）。目录中的 `.cache/huggingface/` 是下载元数据，不按源码阅读。

各模型的额外文件：LLaDA、LLaDA-MoE 和 iLLaDA 的 `tokenizer.json` 保存分词器本体；Dream 的 `tokenization_dream.py`、`vocab.json`、`merges.txt`、`added_tokens.json` 实现并保存其分词规则，`generation_utils.py` 提供生成辅助逻辑；iLLaDA 的 `chat_template.jinja` 是对话模板，`SECURITY.md` 是上游安全说明。其他三个模型虽已下载，项目尚无对应正式适配器。

`runs/` 下的 `cache/`、各次运行目录及其中的 `manifest.json`、`.safetensors`、日志、报告和 `checkpoint/` 都是生成产物。按 `run_report.json` → 对应 `pipeline_report.json` → 阶段 `manifest.json`/报告追踪即可；不要把旧运行产物当成当前源码或正式验收结论。
